## 2. Data model and arithmetic rules

### 2.1 Number domains
| Quantity | Domain | Rule |
|---|---|---|
| Money, prices, fills, stops, costs, NAV, notional ledger amounts | integer micro-AUD `bigint`, rates as exact rationals (D-069/D-070) | unchanged from M3; the float-ban test extends to `src/lib/agents/{batch2b,candidates,controls}.ts` and `src/lib/replay/returns.ts` |
| Price-domain rule comparisons (close ≥ max of 249 closes, close > SMA(n), close > prior close, gap ≥ +8 %, AR thresholds, day-range position) | exact: integers / rationals on raw or factor-adjusted micro prices | `close > SMA200` ⇔ `200·close > Σ closes`; factor adjustment as exact rational from the corporate-action payload, not the REAL `adjustment_factor` column (D-074 precedent) |
| Wilder ATR(20), RSI(2), RSI(14), log-return volatility, percentiles of vol | IEEE float64, fixed evaluation order, Node pinned by `.nvmrc` | decision 8; TA-Lib parity to 1e-6 (AGT-032) |
| ATR entering a stop or a C2 mapping | converted **once**: `atrMicro = round_half_away(atr × 1e6)` from the float via its shortest decimal string (as `toMicroFromVendor`) | stop = `entry − round_half_away(k × atrMicro)` with `k` rational from config; no tick snap (D-076 precedent); IS fills already round per R1 |
| Returns for statistics (ledger rows, controls, daily MTM) | exact rationals from micro amounts, converted to float64 **once** at the statistics boundary (`num/den` division) | statistics in float64, deterministic (2.8) |
| Percentiles for scenario tables | nearest-rank on the exact rationals (no interpolation) | `rank = ceil(p × n)`, 1-based |
| Scores (insider/flow) | integer quarter-units −4…+4 (0.25 = 1) or `NULL` = unknown | never 0 for unknown |

### 2.2 Indicators (A4, AGT-030) on adjusted series (factors with ex-date ≤ D, DAT-126)
- SMA(n)_D = mean of the last n adjusted closes including D (exact rational). Needs n bars, else `null` (condition fails, logged "warm-up").
- TR_t = max(H−L, |H−C_{t−1}|, |L−C_{t−1}|); ATR(20): seed = mean of the first 20 TRs, then `ATR_t = (19·ATR_{t−1} + TR_t)/20` (TA-Lib/Wilder). RSI(n): Wilder averages of gains/losses seeded by simple means of the first n changes; RSI = 100 when avg loss = 0. Warm-up = 3× period before a value is used (TA-Lib's unstable period; parity is checked only after it).
- 6-month return = C_D / C_{D−126} − 1 (exact); percentile within tier = (number of tier codes with a lower return + 0.5 × ties excluding self) ÷ (tier size − 1); "top 20 %" ⇔ percentile ≥ 0.80.
- 250-session high ⇔ C_D ≥ max(C_{D−249…D−1}) (key `F1 high_lookback`, window = lookback − 1 previous closes).
- Volume ratio = V_D ÷ mean(V_{D−20…D−1}) (exact rational; mean 0 → `null`). ADV = mean(close × volume) of the previous 20 sessions on **raw** prices; M3 `marketData.adv` ends on its as-of day, so the agents call it with D−1 (or a new `advPrev20` helper) to exclude D.
- Day-range position = (C − L)/(H − L), 0.5 if H = L (exact).
- Candle patterns (bullish engulfing, hammer, morning star, piercing line): TA-Lib `CDL*` definitions incl. its body/shadow averages over 10 sessions (`BodyLong`, `ShadowVeryShort` settings) reproduced as fixed constants; output boolean per (code, d); stored, informational.

### 2.3 Events (A2, AGT-020) and the decision cut-off
- **Cut-off instant** `cutoff(D)` = D 18:10 Australia/Melbourne → UTC (`localtime.ts`). Decision inputs for D: rows with `published_at < cutoff(D)` (or `ingested_at` when `published_at` is unknown, DAT-001). Bars for D are allowed (Batch 1 publishes them before 18:10); a bar ingested after the cut-off (catch-up) is **not** used for D in live runs — D is then `partial` (AGT-004), never back-filled into D's decision.
- **Day 0** = the trading session during which the item was published; if published at or after that session's continuous-trading end (calendar close − 10 min [VERIFY]; 16:00 normally, 14:00 on early-close days) or on a non-trading day → the next session. An item published after D's close but before `cutoff(D)` has day 0 = D+1 and cannot drive a D+1 order (ARN-020 AC: 18:30 → D+1).
- Untimed backfilled items (`assumed_time`): day 0 = the date if a trading day else the next; usable from that day's cut-off; flagged; the **primary** statistic excludes them, a sensitivity result includes them (ARN-020/082).
- Day-0 return r = C_0/C_{−1} − 1 on adjusted closes (simple, close-to-close); benchmark return b from the index series (2.4); **AR = r − b** (exact rational, stored as integer ppm rounded half-away for display; rules compare the exact rational).
- Category by a **versioned rule table** in code (`EVENT_RULES_V1`): ASX `type` code first, then title patterns (case-insensitive, word-bounded); first match wins; unmatched → `other`. Polarity per AGT-020: + guidance up / contract win / takeover target; − guidance down / capital raising / exchange query / halt; results and others: sign(AR) if |AR| > `event_polarity_threshold` (2 %, B) else 0. LLM category/polarity fields stay NULL in M4 (AGT-011a).
- One event per announcement; several announcements of one code on one day 0 → one **event group** for "one event counts once" (F6 (b)) and "at most one ledger row per event" (ARN-080); group key = (code, day 0).

### 2.4 Regime (A3, AGT-101)
- Benchmark = S&P/ASX 200 index (DAT-010/011), stored daily in `index_bar` (decision 12). Log returns ℓ_t = ln(C_t/C_{t−1}) (float). vol20_D = sample st. dev. (n − 1) of the last 20 ℓ. vol percentile = 100 × (count of vol20 over the trailing 1,260 sessions **before** D with value ≤ vol20_D) ÷ 1,260. fall5 = 1 − C_D/C_{D−5} (exact). SMA200 exact.
- Raw state: SHOCK if fall5 > 7 % or pct > 95; else RISK-OFF if close < SMA200 and pct > 70; else RISK-ON if close > SMA200 and pct < 50; else NEUTRAL.
- Hysteresis (decision 17): SHOCK is entered on the day the raw state is SHOCK. Any **exit** from the current state needs 3 consecutive sessions whose raw state ≠ the current state; the new state is the raw state of the third such session. Warm-up: 1,260 + 20 sessions; before that the state is `unknown` and no family enters (ARN-080 "warm-up before the first decision").

### 2.5 Insider/flow (AGT-105) and short interest
- Score (quarter units) = clip(+2 if net director on-market buys over the last 30 sessions > 0, −2 if < 0; +1 new/increased substantial holder, −1 decreased; −4…+4). Uses notice `published_at`. If no notice source has run for the window (`insider_notice` coverage row absent) → `NULL` (unknown). In M4 every live score is unknown (decision 13).
- Short interest: ASIC daily aggregate `short_pct` stored as integer parts-per-million of issued shares with `as_of` and `published_at` (backfill: assumed `as_of` + 5 weekdays, `assumed_time`, D-065). F6 (d) ⇔ value at the last `as_of` usable at cut-off minus the value 10 sessions earlier ≤ −`short_drop_pp` × 10,000 ppm. Missing either value → class (d) not available (not false).

### 2.6 Stops and exits
- Stop levels are **raw-price micro** levels; initial stops are computed from the actual fill (ARN-021) by an order's `stop_spec`: `{atr_micro, k, cap, level_micro}` → `stop = max(fill − round_half_away(k·atr_micro), cap ? floor_to_micro(fill × (1 − cap)) : 0, level_micro ?? 0)`; F3's initial stop is the day-0 low (`level_micro`), F5 caps at −20 %.
- Every close, batch 2b recomputes each open trade's IS levels (trailing: highest close since entry − k·ATR_D; F3 trail only once a close ≥ entry × 1.10) and appends them to `stop_level` (active from the next session). The **effective** IS level on D = max(initial, all levels written on the latest session before D), re-based by the exact split factor since that row's date (M3 `effectiveStop`). Stops never take a value above the last close (if so the level is still stored; the IS fill rule gaps it at the open).
- CS exits are evaluated by 2b at the close (time stops count sessions held from the entry fill session = 1; F1 "40 sessions held and return < +5 %" uses close/fill − 1 exact) and create `exit_cs` orders for D+1. Event CS exits (F2 − guidance, F5 − polarity) use events with day 0 ≤ D. F6 positions carry the list of contributing families and take the earliest of their exits.

### 2.7 Signal ledger returns (ARN-080/081, VAL-110 v–vi)
- Row: entry at the next open with ARN-032 slippage (P5 profile, the row's ADV bucket), qty = floor(A$600 / entry fill), exit per the family's rules (IS/CS, same fill rules as M3). Amounts: `cost = qty·fill_in + brokerage_in`, `proceeds = qty·fill_out − brokerage_out` (micro). Net return r = proceeds/cost − 1 (rational); **gross** = (qty·raw_open_out)/(qty·raw_open_in) − 1 before brokerage and slippage (ARN-094); **stress** = same with P3 + 50 % slippage (ARN-083/VAL-110 iv); P5 is the absolute-gate profile.
- Matched controls: `c2_controls_per_row` (20) drawn from the path library (4.7); control return c_j computed identically; **paired excess e = r − mean_j(c_j)** (decision 25).
- Daily MTM P/L of an open row on day t = qty × (C_t − C_{t−1}) (entry day: C_t − fill_in − brokerage_in; exit day: proceeds − qty·C_{t−1}); period return = Σ MTM ÷ (A$600 × average open rows in the period); days/weeks with no open row skipped (VAL-110 v/vi).

### 2.8 Determinism (ARN-102, TST-102 for replays)
- No clock reads and no `Math.random` in engine code; randomness from SplitMix64 (`cohort.ts createPrng`) seeded by `deriveRngSeed(ARENA_MASTER_SEED, scope)` with scope strings `c2:<cohort>:<d>`, `lib:<lineage>:<row>`, `boot:<test_id>`, `null:<run>:<i>`, `zeroedge:<family>:<rv>`.
- Every iteration over codes/rows is sorted (code asc, then id); floats are summed in that order (no `reduce` over unordered maps, no parallel workers inside one statistic).
- Outputs are canonical JSON (sorted keys, `canonicalJson`) and hashed (`sha256Hex`); a replay records snapshot hash, commit, params hash and seeds; two runs produce byte-identical files (test).
- Float caveat: `Math.log/exp` are deterministic for one V8 build, not guaranteed across Node majors; replays record `process.version` and a Node upgrade re-baselines the replay digests (decision 8).

## 4. Engine flow

### 4.1 Batch timing (PLT-073 home `02` l.84–99; D-069 #1; D-077)

Agents A2–A4 run inside 2b, so in production data-only mode nothing runs (BLD-024); their outputs are recomputable later from stored data.

### 4.2 A4, A3, A2 (inside 2b, deterministic order A4 → A3 → A2)
1. **A4** (`src/lib/agents/indicators.ts`, `patterns.ts`): for every tracked code (AGT-015) with a bar on D: incremental Wilder state from yesterday's `indicator_daily` row (or a full recompute from bars when absent), write D's row and patterns.
2. **A3** (`regime.ts`): read `index_bar` (≥ 1,281 sessions), write `regime_daily`.
3. **A2** (`events.ts`, `insiderFlow.ts`, `shortInterest.ts`): events for announcements with `published_at < cutoff(D)` not yet recorded whose day 0 ≤ D (AR needs the day-0 bar); scores; short-interest deltas. R2 summaries: optional `card_note`/event notes through the router (4.6); none in rules-only mode.
4. Each agent writes `schema_version`, `agent_version` (code constant), `inputs_ref` (run id of Batch 1 + max `ingested_at`), `decided_at` (AGT-002). A failure is caught per agent; downstream steps run, outputs `partial` (AGT-004).

### 4.3 A5 families (pure rule interpreter, `src/lib/agents/families/*.ts`; one implementation for live and replay, AGT-003)
Each family is a pure function `(DecisionView, params, variant) → {candidates[], exits[], stops[]}` where `DecisionView` is the only data interface (live: Turso reader bounded by D and `cutoff(D)`; replay: snapshot reader with the same bounds; both throw `LookAheadError`).

### 4.4 Candidate selection, sizing and orders (batch 2b, per live cohort; cohort id asc)
1. Read the closed ledger (2a): cash, open trades, sleeve state, `max_open_positions`.
2. **Exits first:** for every open trade evaluate CS rules → `exit_cs` order for D+1 (one per trade); append recomputed IS levels to `stop_level`.
3. **Re-entry block** (FAM-002): drop candidates whose code had an IS exit for this **execution** (any cohort) within the last `reentry_block` sessions (decision 18).
4. **FAM-001:** sort candidates by rank; one slot free → top-ranked sized by M3 `sizeEntry` (ARN-024a) on post-event terms (corporate actions with ex-date D+1 applied to the reference price, removing `order_qty_stale`, D-077); two slots free and ≥ 2 candidates → open both only if `sizeEntry` on 50 % of deployable each passes the parcel after costs; F4 in SHOCK → deployable × 1/2, only if it still meets the parcel. 5. Write `arena_order` (`entry`, `ref_stop_micro` = NULL, `stop_spec`, `max_open_micro`, `signal_id`, `card_id`) and the card in one transaction; every candidate not taken gets a card with `not_taken_reason` (rank, cash, parcel, positions, block, gate, regime).
6. **C2/C3 executions** (decision 33): for each E-execution entry of family f on D, each live C2-f/C3-f cohort draws one control code with its PRNG from the pool = same tier, same `vol_decile` (deciles of vol20 over that tier's eligible codes on D), passing the same filters, excluding the signal's code and codes with a same-day qualifying signal or event for f; a control holding a position or unable to afford the parcel **skips** (`c2_selection.skipped`); exits by M3 `mapControlExits`. Skip rate is a replay statistic.
7. Run record counts only (signals, orders, cards, skips). Idempotent: ids are deterministic, writers `ON CONFLICT DO NOTHING`, `hasSuccess` blocks reruns.

### 4.8 Validation statistics (ARN-081…087, VAL-102; `src/lib/stats/*`, HR)
1. **Lineage and splits** (`splits.ts`): lineage = `<market>:<family>` (ch.05 §5.1); at creation: default layout 378/504 with purge = upper bound of the max-holding parameter + 20 (F1 140, F2 110, F3 60, F4 40, F5 65, F6 60) and completion window = purge; measure **block** = max(5, p75 of realised holding sessions of the v1 primary-variant ledger rows with entry before (default validation start − purge)); window lengths = max(378, 15·block), max(504, 15·block); development < 252 sessions → `deferred_until_d`. Frozen in `lineage_split` v1; re-measured only at a roll (ARN-082; challengers/rolls are M6, the record supports them).
2. **Circular block bootstrap** (`bootstrap.ts`): index the tested window's entry sessions 0…S−1; blocks of `block` consecutive sessions, wrapping; a replicate draws ⌈S/block⌉ block starts uniformly (PRNG) and collects the rows whose entry session falls in them; statistic per replicate = mean of centred excesses (e − ē) of the collected rows (replicates with 0 rows are redrawn, counted). se = SD of the B replicate means; t = ē/se; null t* = replicate mean/se; **p = (1 + #{t* ≥ t})/(B + 1)** (one-sided). S/block < 15 → "insufficient independent blocks" + reachable date (from the measured signal rate).
3. **Levels:** α = 0.05; VAL-110 (i) and (ii) and ARN-084 at α/(m·L) with m = `trial_budget_per_lineage` (20) and L = max(6, active lineages) → 0.000417; holdout confirmation at α/L; B = max(1,000, ⌈20/level⌉) → 48,000; size checks B = 2,000 (decision 24). Every result stores level, B, n, blocks, L and m used.
4. **MDE** = (z_{1−level} + z_{0.80}) × se (normal approximation, stated as such). **Absolute gate:** one-sided 90 % lower bound of mean net return under P5 = 10th percentile of B replicate means of raw (uncentred) net returns > 0. **Two-sided 90 % interval** of mean excess (FAILED/NOT-DEMONSTRATED, ARN-086) = 5th/95th percentiles of uncentred replicate means; FAILED if U < `useful_edge_min`.
5. **VAL-110:** (i) p ≤ level and absolute gate; (ii) challengers only (engine + test; no challengers in M4); (iii) safety: Δ(bust + stalled) CIF(252) vs C2 from rolling-start cohorts on development + validation, non-overlapping (effective N); blocks only when effective N ≥ 8 and Δ > `delta_bust_tolerance`, else descriptive with first-block date; (iv) stress point estimate > 0; (iv-b) not cost-infeasible; (v) PBO; (vi) DSR. Each access writes a `trial_ledger` row **before** the test reads the validation rows.
6. **PBO** (`pbo.ts`, CSCV): matrix of weekly returns (T weeks × N tested variants of the lineage), S = 10 contiguous blocks of weeks (last block takes the remainder), all C(10,5) = 252 IS/OOS splits, Sharpe per variant, logit of the IS-best's OOS relative rank; PBO = share of logits ≤ 0; N < `pbo_min_variants` → "n/a".
7. **DSR** (`dsr.ts`): daily returns; SR, skew γ3, kurtosis γ4 (not excess); SR0 = √V × ((1 − γ_E)·Φ⁻¹(1 − 1/N) + γ_E·Φ⁻¹(1 − 1/(N·e))), γ_E = 0.5772156649; N = lineage trials on this split; V = variance of daily SR across tested variants, or `dsr_default_sr_variance` (variance of the 6 families' daily development SR, frozen per split) when < 5; N = 1 → SR0 = 0; DSR = Φ((SR − SR0)√(T − 1)/√(1 − γ3·SR + (γ4 − 1)/4·SR²)). Φ and Φ⁻¹ implemented in code (erfc series / Acklam with one Newton step), unit-tested to 1e-9.
8. **Labels** (`labels.ts`, ARN-086): per (execution, rule version, variant): UNVALIDATED → PASSED-BACKTEST (VAL-110 + one holdout confirmation) → CONSISTENT-FORWARD (forward looks at 100·k trades, α = (0.10/L)/2^k, ≥ 6 months, absolute > 0, forward CIF inside the backtest 90 % prediction interval); FAILED / NOT-DEMONSTRATED; UNVALIDATABLE (event coverage < 90 % over the tested dates, DAT-127); "insufficient evidence" (< 100 rows or < 15 blocks) with its date; "possible luck". Qualifiers: survivorship-exposed (x %), "C2 exit-mapping bias (ARN-004)" for event families, the v1 knowledge note, "live rule ≠ validated variant", F5 descriptive-only; `cost_infeasible` flag (decision 29). U1/U2 and F5 coverage per ARN-082/DAT-130.
9. **Survivorship** (`survivorship.ts`): per calendar year, codes with ≥ 3 announcements in the previous 60 sessions (DAT-125 list) and no price history ÷ all such codes; > `survivorship_flag_share` → exposed; results with and without exposed years; delisting sensitivity re-scores rows in codes delisted within their hold at the last traded price (or −100 %), with the stated limitation. Code reuse split by announcement history (flag only in M4: detection rule = a gap ≥ 120 sessions with a name change in `instrument`).
10. **Trial budget** (ARN-085): remaining = m − accesses on the current split; at a roll, new budget = m − ⌈accesses_old × overlap⌉ with overlap = shared sessions ÷ new validation sessions (decision 26).

### 4.9 AT-17 null runs and injected edge (`scripts/replay/nullRuns.mjs`, `kind=null|injected`)
- **Null:** 2,000 runs; each run takes the real snapshot, a random-signal "family" (per entry session, each eligible U1 code is a signal with probability q chosen so the expected row count matches F1's measured rate; PRNG `null:<run>:<i>`), the F1 exit rules and the same control library; full ledger + controls → ARN-081 test at B = 2,000; record p. Pass: rejections at 0.05 and 0.01 inside the exact two-sided 99 % binomial acceptance region for n = 2,000; **uniformity:** KS test of {p/0.10 : p ≤ 0.10} against U(0,1) not rejected at 0.01; report (not pass) the empirical rate and Clopper–Pearson interval at 0.0025 and 0.000417.
- **Injected edge:** synthetic snapshot (public generator, ZZ codes) where signal rows earn +1.5 % net over their matched controls with noise; pass = p ≤ 0.000417 at B = 48,000 on the committed seed; plus a "< 15 blocks" window returning "insufficient independent blocks".
- Runs in the replay workflow (`production` env, data-repo read only for history files, aggregates only in logs/run records, no artifact, SEC-110; decision 31). Minutes measured and reported.

### 4.10 Kill switch (ARN-093) and cost feasibility (ARN-094)
- Batch 3 after each forward ledger close: at forward trade counts 20·k (k ≤ K), per family/rule version, three criteria at α_k = (0.05/3)/2^k: (1) block-bootstrap one-sided test of mean(forward net − backtest development mean) < 0 (ARN-081 procedure, lineage block); (2) exact binomial lower tail of forward wins vs the development win rate; (3) once forward effective N ≥ 3: exact binomial lower tail of forward CIF_target(t_max) vs the backtest 90 % lower bound. A trigger writes `killswitch_look.triggered = 1` and `arena_control` (`killed`, family) → 2b creates no new entries for that family; exits continue. K = `killswitch_max_looks_per_year` computed each 1 January (and at first evaluation) as max(1, ⌈expected forward trades per year ÷ 20⌉) from the development signal rate, stored as a computed config version (decision 28).
- **Cost feasibility:** round-trip cost = 2 × P5 brokerage at A$600 (A$10) + 2 × the median modelled slippage (bps) of the family's development rows × A$600; flag when development gross mean per-trade return × A$600 < `cost_feasibility_ratio` × cost; blocks PASSED-BACKTEST (iv-b).
