## Summary and "done"

- **Steelman** (PRD-029, AGT-131/133): after the night's cards and picks are final, a new, separate bundle `steelman` builds a deterministic evidence pack per subject (orders by `signal.rank_score`, then picks; at most `steelman_daily_cards`), asks one R6 author for 2–4 bull and 2–4 bear points that cite pack IDs, validates every claim app-side (LLM-064/065), has an A7 Critic on a **different provider** check the survivors, stores pack and points append-only, records one `opinion_track` row (kind `steelman`, CTX-041), and lists `monitorable` bear points as Owner `/review` suggestions (AGT-133a). Nothing in it can reach an order, a breaker or a rule (PRD-033): the modules have no writer into those tables and a static test proves it.
- **Picks vs market** (PRD-030, ARN-103/104): when `trackPicks` settles a pick (closed) or marks it missed, the same transaction writes one immutable `pick_market` row: market total-return over the holding window from `benchmark.ts`, vs market in ppm, basis label. The track record shows "vs market +x.x pp" per settled row and the per-profile summary (median, share beating, n; n < 30 → "insufficient history"; "past paper picks, not a forecast").
- **Reflections** (AGT-134) are optional and last (WP8), only if budget remains (BLD-046).
- **Production reality (D-480).** Every LLM role in production is rules-only until its bake-off passes (D-177: `src/lib/arena/cli.ts` `rulesOnlyLlm`, providers `[]`; the only live-provider caller is `src/lib/llm/bakeoffCli.ts`). So on staging and at the V2 PR the steelman section reads "not written tonight (no model available)" and nothing else changes. The whole path is proven with the mock provider and recorded fixtures; the live wiring is one router factory the Owner enables after the R6 bake-off (listed in the PR).

Done = AT-32 (steelman part), AT-33, AT-34, AT-35, AT-37 (steelman part) green locally and in CI; ≥ 50 R6 golden items with the bake-off report under `docs/test-reports/`; the static boundary test green; Blueprint completeness check green; `docs/M11L_exit_evidence.md` with the BLD-041 row "pending production".

## Schema: migration `0021_steelman.sql` (needed)

Conventions of 0019/0020. Session dates GLOB, JSON `json_valid`, money integer micro, ppm integers, ISO UTC text.

- `steelman_pack`: `pack_id TEXT PK` (= `sha256(canonical pack json)`), `market`, `d`, `subject_kind CHECK IN ('order','pick')`, `subject_id` (order: `decision_card.id`; pick: `market|d|profile|rank`), `code`, `card_id` (nullable for a pick without a card), `cutoff_at`, `items_json` (array of `{ id, kind, text, at? }`), `item_count`, `created_at`; `UNIQUE (market, d, subject_kind, subject_id)`; no_update, no_delete.
- `steelman_point`: `point_id TEXT PK` (`<pack_id>:<side>:<n>`), `pack_id` (guard: must exist), `side CHECK IN ('bull','bear')`, `n`, `text` (≤ 40 words checked app-side), `citations_json` (non-empty array of pack item ids), `monitorable INTEGER CHECK IN (0,1)` (bear only; 0 for bull), `state CHECK IN ('shown','hidden_critic','dropped_citation','dropped_number','dropped_unsafe')`, `author_provider`, `author_model`, `critic_provider`, `critic_model`, `critic_note`, `created_at`; no_update, no_delete. A hidden or dropped point is stored (the log), only `shown` renders.
- `steelman_night`: `market, d` PK; `requested, written, not_written_limit, not_written_budget, not_written_no_model, not_written_critic, claims_total, claims_valid, validity_ppm, critic_hidden, created_at`; insert-once (no_update, no_delete). BLD-041 evidence row.
- `steelman_suggestion`: `suggestion_id TEXT PK` (= `point_id`), `market`, `d`, `point_id` (guard: exists, side bear, monitorable 1, state shown), `card_id`, `code`, `family`, `status CHECK IN ('open','dismissed','expired')`, `created_at`, `closed_at`, `closed_by` (user id or `'system'`); trigger `steelman_suggestion_guard_update`: abort unless `OLD.status = 'open'` and only `status`, `closed_at`, `closed_by` change; no_delete.
- `pick_market`: `market, d, profile, rank, kind` PK (same key as `pick_outcome`; insert guard: the outcome row exists with state `closed` or `missed`), `window_from_d`, `window_to_d`, `index_code`, `basis CHECK IN ('price_only','total_return')`, `index_from_micro`, `index_to_micro`, `market_ret_ppm`, `pick_net_ppm` (NULL for missed), `vs_market_ppm` (NULL for missed), `missed INTEGER CHECK IN (0,1)`, `settled_d`; no_update, no_delete (AT-35 "cannot be edited").
- `pick_reflection` (for the optional WP8; harmless if unused): `market, d, profile, rank` PK, `text`, `agreed_point_ids_json`, `provider`, `model`, `state CHECK IN ('written','not_written')`, `reason`, `created_at`; no_update, no_delete.
- `+down` drops the six tables. `src/lib/data/schema.ts` table list updated if it enumerates main tables (check at build; 0020 did not need it for its tables).

## Interfaces

- `src/lib/steelman/subjects.ts`: `nightSubjects(db: Exec, market, d, max: number) → Promise<Subject[]>`; `Subject = { kind: "order" | "pick"; id; code; cardId: string | null; rankScore: number | null; pickKey?: { profile; rank } }`. Orders = `decision_card` rows decided on `d` with `taken = 1`, joined to `signal.rank_score`, descending; then `pick` rows of `d` by `profile, rank`; cut at `max`.
- `src/lib/steelman/pack.ts` (pure core + small reader): `buildPack(input: PackInput) → EvidencePack`; `EvidencePack = { packId; items: PackItem[]; cutoffAt }`; `PackItem = { id: string (E01…E40); kind: "card" | "rule" | "regime" | "event" | "insider" | "factor" | "scenario" | "liquidity" | "cost" | "flag" | "headline" | "pick_level"; text: string; at?: string }`; `loadPackInput(db, subject, d, params) → PackInput` reads `decision_card.card_json` (events, rules fired, scenario percentiles with n, sizing/liquidity and cost buckets, data-quality flags, cortex block), the regime row, insider score, factor rows (`readFactorRows`), pick levels, and up to `evidence_pack_max_items` announcement headlines for the code with `published_at <= decisionCutoffUtc(d, decision_cutoff)` plus the stored Sentinel summary where one exists. `packId = sha256Hex(canonicalJson(items))`. Headline/summary items are the only untrusted text: they go in `untrusted` (datamarked, filtered by the router), never in `facts`.
- `src/lib/steelman/claims.ts` (pure): `STEELMAN_SCHEMA` (object: `bull: Point[2..4]`, `bear: Point[2..4]`; `Point = { text: string; citations: string[1..]; monitorable?: boolean }`), `validatePoints(raw, pack) → { kept: Point[]; dropped: { point; reason: "citation" | "number" | "unsafe" | "length" }[]; rejected: boolean }`; a number in `text` must appear verbatim (after `normalizeNumber`) in a cited item's text; `UNSAFE_RE` = URL, code fence or backtick, imperative-to-system phrases (reuse `DEFAULT_INJECTION_PHRASES`); `rejected = dropped > kept.length` or either side < 2 after drops. Also `steelmanCheck(pack)` = the router `check()` that returns `{ ok: false, field: "bull" | "bear" }` when the response would be rejected (so the router's single repair fires, D-487).
- `src/lib/steelman/critic.ts`: `criticChain(providers: readonly LlmProvider[], author: { provider; model }) → { chain: string[]; rule: "different-provider" | "skip" }`; `CRITIC_SCHEMA` (`verdicts: { pointIndex; supported: boolean; note }[]`); `applyCritic(points, verdicts) → { shown; hidden }`.
- `src/lib/steelman/write.ts`: `writeSteelman(deps: { db: Exec; authorRouter: LlmRouter; criticRouterFor(author): LlmRouter | null; params; now }, subject, pack) → Promise<WriteOutcome>`; `WriteOutcome = { state: "written"; shown: number; hidden: number } | { state: "not_written"; reason: NotWrittenReason }`; `NotWrittenReason = "daily_limit" | "budget" | "no_model" | "critic_unavailable" | "rejected"`. Stores the pack first, then every point with its state, then `recordOpinion` (D-488).
- `src/lib/steelman/night.ts`: `steelmanNight(db, o: { market; d; params; routers; calendar; now }) → Promise<NightResult>`: settle due opinions (read-after), expire suggestions, pick subjects, write at most `steelman_daily_cards`, insert the `steelman_night` row, insert suggestions for shown monitorable bear points. Idempotent per `(market, d)` via the `steelman_night` insert-once row. Every step is in its own try/catch: a failure writes `not_written` and never throws past the CLI (the night is never blocked, D-484).
- `src/lib/steelman/cli.ts`: `steelmanMain(argv, env, deps)`; `scripts/arena/signals.mjs` calls it after `picksMain` and reports the max exit code (a steelman failure exits 0 with a logged `degraded`, D-484).
- `src/lib/steelman/opinion.ts`: `opinionValue(points) = { bull: n, bear: n, monitorable: n }`; `settleDue(db, market, d)`: for each unsettled `steelman` opinion, order subjects settle when the linked `trade` row of the order has closed (outcome = sign and ppm of its net), pick subjects when `pick_outcome.state = 'closed'` (outcome = `net_ppm`); missed picks settle with `outcome: { missed: true }`.
- `src/lib/steelman/suggestions.ts`: `openSuggestions(db, market) → SuggestionRow[]`; `dismissSuggestion(x: { mainDb; authDb; env; meta; actorId; id }) → Promise<{ ok: true } | { error }>` (status → dismissed, then `audit(... "steelman_suggestion_dismiss" ...)`); `expireSuggestions(db, market, d, calendar, sessions) → number` (open rows whose creation session is ≥ `sessions` trading days before `d` → `expired`, `closed_by 'system'`).
- `src/lib/steelman/read.ts` (UI reader): `readSteelmanForCard(db, cardId) → SteelmanView | null`; `SteelmanView = { state: "written" | "not_written"; reason?: NotWrittenReason; bull: PointView[]; bear: PointView[]; cited: PackItem[] }`; `PointView = { text; citations: string[]; monitorable }`.
- `src/lib/picks/vsMarket.ts`: pure `windowReturnPpm(series: TotalReturnPoint[], fromD, toD) → { fromMicro; toMicro; retPpm } | null` (level at the last session **before** `fromD` to the level at `toD`, D-490), `vsMarketPpm(pickNetPpm, marketRetPpm) = pickNetPpm − marketRetPpm`; `pickMarketStatement(db, market, key, sim, basis, series) → InStatement | null` (the INSERT the `trackPicks` loop adds to its batch); `vsMarketSummary(rows) → { n; medianPpm: number | null; beatingPct: number | null; insufficient: boolean }`.
- `src/lib/llm/dropOrder.ts`: `DROP_ORDER = ["expert_ingest", "committee", "company_overview", "news_summary", "steelman", "pick_reflection", "evening_review"] as const`; `reserveAfter(stage, params) → number` = the sum of the daily caps of the stages after `stage` that exist in code today (R5 for `evening_review`; the reflection share of R3 for `pick_reflection`, D-482). The steelman stage refuses a call when `totalRemaining − reserveAfter("steelman") < reservation`.

## Risks

- **No live model in production**: everything shows "not written tonight (no model available)" until the Owner wires a live router after the R6 bake-off; the PR says so plainly (D-480). The whole path is only mock-proven until then.
- **Free-tier limits**: Groq rows carry 200K tokens/day per model and 8,000 TPM; 240,000 tokens/day across roles fits only across two or more models/providers; the R6 request budget (`dailyRequests`) and the daily token caps make the steelman shrink first (D-481).
- **Pack leakage of untrusted text**: headlines and summaries are the only third-party text; they go to `untrusted`, are datamarked and injection-filtered; trains-on-prompts providers never see them (router rule). A provider that sees facts only still gets every structured item.
- **Decision-path leak**: write allowlist, import guard, hash identity, no batch2b/batch3 edit.
- **`trackPicks` change**: the `pick_market` INSERT joins the existing per-pick batch; a wrong statement would abort the settlement write. Mitigation: unit tests over the closed and missed edges, and `pickMarketStatement` returns `null` (no row, logged) when the index series is missing, never an error.
- **Suggestion expiry drift**: counted in trading sessions from the calendar; the test fixes DST and holiday cases.
- **Public repo**: packs and recorded answers are synthetic ZZ data; no real headline text.

- **D-503** Night stage details (WP4). (a) Counting on `steelman_night`: `daily_limit` → `not_written_limit`, `budget` → `not_written_budget`, `no_model` and an unexpected error → `not_written_no_model`, `critic_unavailable` and `rejected` (the answer did not pass the claim checks, or the critic hid every point) → `not_written_critic`; `claims_valid` = points that passed the claim checks (shown or critic-hidden), `claims_total` = every point the author wrote; a night with no claims stores `validity_ppm` 0. (b) A pack is stored before the room check, so a "not written" subject still has its pack on file; a re-run reuses the stored pack and, when points are on file, does not call a model again. (c) Pack identity: the night stage puts a first `card` item `Subject <kind> <code>` ahead of the loaded items, so two subjects with identical evidence do not share a `pack_id` (the card thesis is a fixed per-family line). (d) The reservation (author plus a worst-case critic call) must fit under the role, total and nightly caps, and the total left minus the market-scaled caps of the later stages (`reserveAfter`, scaled by the market share) (D-482). (e) A critic that answers from the author's own provider is refused even if a router returned it (D-483). (f) A pick with no card gets no Owner suggestion (no family to point the rule editor at). (g) The CLI imports no arena module and, of `src/lib/agents`, only `params` (the typed parameter loader; PRD-033 boundary): the calendar and the reviewed-night key are read in `cli.ts` itself; the three steelman keys are read from `config_version` with the registry default.
- **D-504** (WP4 review) `scripts/arena/signals.mjs` loads and runs the steelman bundle inside its own try/catch after the picks: a bundle that fails to build (a bad import would do it) or a stage that throws past its guard logs one `arena-steelman: degraded (stage not run: <error name>)` line and the night's exit code is the picks' code, unchanged. A steelman failure cannot fail the night (D-484), not even before `steelmanMain` runs.
- **D-505** (WP4 review, D-482 refined) The reserve for the later stages is what they still have to spend, not their whole caps: `reserveAfterLeft(stage, params, market, usage)` sums, over the stages after `stage`, `max(0, scaledCap(cap, share) − roleDay)`. The Evening Review text is written in batch 3 (`words` phase), before the picks and the steelman, so on a normal night R5 has already spent and the steelman is not made to reserve its share twice. The reserve is taken from the daily total and from the nightly per-market cap alike (`nightly_tokens_per_market` 30,000 binds before the 240,000 total for one market, and the Evening Review is a nightly call), so `hasRoom` = reservation ≤ min(role/total/nightly allowance, totalLeft − reserve, nightLeft − reserve). The builder's market scaling of the reserve stands (every cap in `budget.ts` is scaled by the market share).
- **D-506** (WP4 review, D-503c refined) The first pack item names the subject, not only the code: `Subject order <code>, card <id>` or `Subject pick <code>, profile <p>, rank <n>` (`subjectLine` in `night.ts`). Two profiles may pick one code on the same night with the same levels; with a code-only line those two packs would hash alike and the second subject would end as `error`. The golden set and the claim checks are untouched (the line is a `card` item like the thesis; it carries the rank as its only number).
- **D-507** (WP4 review) The `opinion_track` row is a side track (CTX-041): a failure to insert it after the points are stored does not turn a written subject into `not_written` (the points are shown). The night stage re-records the opinion (idempotent: same value, same id) for a subject it finds already written on a resume, so a run that crashed between the points and the opinion row still gets its opinion on the next run.
- **D-508** (WP4 review) Settlement precedence: when an order pack exists for the opinion's code and night, only the order's closed trade settles it (orders come first, AGT-133, and the opinion was written for the order); a pick's outcome settles it only when no order was taken for that code. Before, whichever subject closed first decided.
