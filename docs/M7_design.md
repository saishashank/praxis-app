## 2. Architecture

### 2.1 Next.js App Router conventions in this repo
- Next 16.4, React 19.3, Tailwind 4.3 (`@theme static` tokens in `globals.css`), `src/proxy.ts` (Next 16 proxy, Node runtime) → `src/lib/http/gate.ts`. Signed-in pages live in the route group `src/app/(app)/`; public pages are `signin`, `privacy`, `terms`; `robots.ts` disallows all (PLT-036).
- **New `src/app/(app)/layout.tsx`** renders the shell (§4.2). It reads the user with `getCurrentUser()` only to choose menu items; it is **not** a guard (layouts do not re-run on every client navigation, and D-038 puts the guard in each page). Every `page.tsx` keeps `await requireUser(action, path)` as its first statement; a unit test walks `src/app/(app)/**/page.tsx` and fails if the first awaited call is not `requireUser` (extends the TST-122 idea to pages).
- Every page is `export const dynamic = "force-dynamic"` (the root layout already calls `connection()` so the per-request CSP nonce reaches Next's scripts). URL search params carry tab, chip, sort, filter, profile and range state (server-rendered, shareable, back-button friendly); client state is limited to islands (§4.1).
- New `error.tsx` in `(app)` and `global-error.tsx` show a generic message with the Next error **digest** as correlation id (UX-122); the server-side `onRequestError` hook (`src/instrumentation.ts`) writes the digest, path and error class to `app_log` (Owner-only, PLT-040 redaction). `not-found.tsx` per group.

### 2.2 Server components and server actions
- Pages and all data-bearing components are **server components**. They call a page loader (§2.7) that returns a plain, serialisable, already-masked view model. Client components receive only those view-model props.
- Mutations are **server actions** in `actions.ts` files with a top-level `"use server"` (picked up by `scripts/ci/route-coverage.mjs`), or the existing route handlers where they already exist (alerts D-101, annotations D-125, learning owner actions D-125). Each action: `requireUser(action, path)` first, input validation, Owner actions audit-first (D-047/D-125 pattern) with `confirm: true` for irreversible ones, `revalidatePath` of the page, no state change via GET (SEC-011; the gate refuses cross-origin writes, D-036).
- New actions (TST-122 rows required): `toggleWatchlistAction`, `cycleThemeAction`, `setSortPreferenceAction`, `grantUnmaskAction` / `revokeUnmaskAction`, `setArenaControlAction`, `tickOpsTaskAction`, `runWhatIfAction`. Appearance and region fields extend the existing `updatePreferencesAction`.
- New route handlers (all `withAuth`, JSON, `Cache-Control: no-store`): `GET /api/news/[id]` (news pop-up, UXN-038), `GET /api/market/[code]/overview` ("i" panel, UXN-272), `GET /api/market/search` (instant search, UXN-270), and the carried `GET /api/learning/plan`, `GET /api/learning/documents` (D-125).

### 2.3 Auth guard and role checks
- `requireUser` / `withAuth` (D-038) with the ROL-102a actions in `src/lib/auth/permissions.ts` (`read`, `own_preferences`, `annotate`, `what_if`, `unmask`, `admin`). Page actions: Home, Picks, Market, Strategies, News, Reviews, Glossary, Control Room = `read`; Settings personal / appearance / region display = `own_preferences`; About = `read`; Usage, Ops, Users, Configuration, Data review = `admin`; What-if = `what_if`. One new action **`watchlist`** (Owner, Editor; decision 9) is added to the matrix with a test.
- UX-004: controls a role cannot use are **not rendered** for Viewers and rendered **disabled with the reason text** for Editors (one `<RoleGate>` helper takes the user's role and the action; UXN-015 keeps the reason visible when disabled). The server action refuses regardless.
- Masking and role filtering happen in the loader (server); a client component can never receive a field the role may not see.

### 2.4 Masking (UX-009, ROL-107; decision 41; high risk)
- `src/lib/ui/mask.ts` (pure, `server-only`): `maskContext(user, d, grants)` → `{masked: boolean}`; Owner and users with a live `unmask_grant` are unmasked. For masked users: **active set** = every code in any record the loader returns for that Melbourne date (collected first, then masked); letters assigned alphabetically by code ("Stock A", "Stock B", … "Stock AA"), fixed for the whole date; trade prices, company names, evidence links and source links removed; exact trade dates → ISO week (`2026-W38`); sector and tier kept. Per UX-009 table: tiles/leaderboard show no codes; Signals, Decision Cards, Risk positions, alert inbox, execution trade lists and in-app reviews use letters; News shows macro/regulator items and company items only for unmasked users; Knowledge shows rules-only template text; annotations on masked content show "Note added by <role> on <date>" (D-125).
- Market and company pages (public company data) follow decision 21.
- `unmask_grant` (auth DB 0006): user, granted_by, granted_at, expires_at (default `unmask_expiry` 30 days, `15` l.171), revoked_at; Owner action audit-first. Loaders read grants once per request (`cache()`).
- Tests: property test (random records → no code, name, price, exact date or URL survives for a masked context; letters stable within a date and reset across dates), and an E2E check that the Viewer and Editor HTML of every page contains no fixture code string.

### 2.5 Themes and tokens (D-048, D-049)
- One token set, six `data-theme` blocks in `src/styles/themes.css`, applied server-side on `<html>` from `user_preference` (no inline script). M7 adds token families, one declaration per line so `scripts/ci/contrast-check.mjs` parses them: `--color-regime-{shock,riskoff,riskon,neutral}`, `--color-label-{unvalidated,passed,consistent,failed,notdemo,unvalidatable}`, `--color-breaker-{green,amber,red}` (not the gain/loss pair, UXN-001), `--color-chart-{1..4}`, `--color-grid`, `--color-surface-2`, `--color-danger` (destructive buttons), and `--font-mono`. The contrast checker gains the new text/background and UI pairs (AA 4.5:1 text, 3:1 graphics; AAA 7:1 in high contrast).
- Gain/loss always render through `<GainLoss>` (sign + ▲/▼ + colour + `aria-label`, UXN-001); colour is never the only signal. The "Classic green/red" option waits for decision 6.
- Theme change applies without reload: the action updates the preference and `revalidatePath("/", "layout")`; the header shortcut (UXN-280) is a form button calling `cycleThemeAction`. "Match device" keeps the existing media-query block.

### 2.6 CSP nonce (SEC-012)
- Unchanged policy (`src/lib/http/csp.ts`): `script-src 'self' 'nonce-…' 'strict-dynamic'`, `style-src 'self' 'unsafe-inline'`, `img-src 'self' data:`, `font-src 'self'`, `connect-src 'self'`, `frame-ancestors 'none'`. Every new library must work under it (decision 17): Lightweight Charts draws on `<canvas>` (no eval, no remote fetch); Radix positions with inline style attributes (allowed by `style-src`); fonts are self-hosted by `next/font` at build. No CDN, no remote images (UX-006). A test asserts `script-src` never contains `unsafe-inline`/`unsafe-eval` (production) and that no directive lists an external host except `form-action https://accounts.google.com`.

### 2.7 Data loaders over the existing libraries
- One loader module per page area in `src/lib/ui/loaders/` (`import "server-only"`): `home.ts`, `strategies.ts`, `risk.ts`, `ideas.ts`, `cards.ts`, `picks.ts`, `market.ts`, `news.ts`, `alerts.ts`, `reviews.ts`, `knowledge.ts`, `health.ts`, `usage.ts`, `settings.ts`, `shell.ts`. Each takes `(db handles, user, params)` and returns a typed view model with `state: "empty" | "stale" | "ok"`, `asOf` (last good timestamp) and the masked payload.
- Loaders reuse the existing readers: `getHealthSummary`, `loadAttentionItems`, `health/components` (nine Control Room components, D-108), `usage/meters`, `alerts/api` (inbox, unread counts, quiet hours; D-101), `review/*` (stored `evening_review`, section 7a reader D-122), `picks/{store,success,section7a}`, `learning/ownerActions` (lists, annotations), `kb/documents`, `agents/{cards,decisionView,regime}`, `arena/{nav,cohort}`. New SQL reads go only into the loader modules (no SQL in pages); every query is bounded (limit, date window ≤ 500 sessions, DAT-140) and uses an existing index or one added in main 0011.
- Staleness (UX-007, PLT-017): `src/lib/ui/staleness.ts` maps each page's source to its job's expected interval (from `health/jobs.ts`) and flags data older than 2×; the `<StaleBanner>` shows the last good time.
- Honesty helpers: every money value comes out of the loader as `{micro, currency, simulated: true}` and renders through `<Money>` which carries `data-money` and a visible or adjacent "Simulated" label (AT-27); probabilities are only rendered through `<Probability>` which requires a calibration-report id or prints "not yet calibrated" (VAL-101); unmeasured metrics are `null` and render "not yet measured" (REV-003).

### 2.8 No client-side secrets
- Loaders, `src/lib/db/*`, `src/lib/auth/*` and every module that reads `process.env` import `server-only`; an ESLint `no-restricted-imports` rule forbids `@/lib/db`, `@/lib/auth`, `@/lib/config` and `@/lib/ui/loaders` inside files with `"use client"`. The existing client-bundle secret scan (D-041, `scripts/ci/bundle-secret-scan.mjs`) runs on every build. No `NEXT_PUBLIC_*` variable is introduced.

### 2.9 Caching
- HTML and JSON are per user: `Cache-Control: private, no-store` (routes already; pages are dynamic). No Next data cache / `use cache` for anything role- or user-dependent.
- Per request: React `cache()` for the user, grants, preferences and the market status (shell + page share them).
- In-process memo (as the D-047 config cache) for **market-wide nightly aggregates** only (Market movers, universe list, sector grid, leaderboard rows before masking), keyed by `(market, latest completion_marker d)` with a 10-minute ceiling; masking is applied after the cache. Control Room refresh uses `router.refresh()` every 60 s while `document.visibilityState === "visible"` (decision 24).

### 2.10 Empty, stale and error states
Each page defines three states with fixed text: **empty** (no cohort / no data yet, e.g. "No rounds yet — the strategies start when the market is switched on"), **stale** (banner with last good time), **error** (section-level "Could not load this part" + correlation id, the rest of the page still renders via per-section `<Suspense>`/error boundaries). "SAMPLE DATA" appears only in test fixtures and screenshots made from them (UX-102); production pages never show sample rows.
