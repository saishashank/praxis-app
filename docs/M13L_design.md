## Summary and "done"

- **What ships.** The expert data model (experts, red flags, source items, claims, clusters, screening, proposals, calls) in main-database migration `0022_experts.sql`; an Owner-run seed import `scripts/experts/import.mjs` in the Cortex-import pattern (format `praxis-expert-seed/1`, folder outside the repo, validated before any write, counts only); a private-side converter that turns `docs/23`/`docs/24` into that format; a weekly `experts` learning stage that screens eligible clusters on the development split only with BH at `expert_screen_fdr` and proposes at most `expert_challengers_per_week` survivors through the existing `createChallenger`; the dormant F7 gate; a deterministic scorecard; the vocabulary-gap report; a calls store with a paper tracker for active-market codes; four pages (directory, detail, techniques, claims queue); licence-register rows for the DAT-227 channels; four config keys.
- **What is a hypothesis and what trades.** Every imported claim is L0 and `extracted` (D-512). Nothing is screened until a person confirms it (LLM-069). A cluster can be screened only when it is expressed as a **parameter set of a v1 family F1–F6** (D-514): KB-010 says parameters are the only degree of freedom of a rule version and a structural change is a new lineage (FAM-101), and the arena executes only `FAMILY_SPECS`. Clusters that need a new structural rule are stored and shown with the reason and wait for a build change (D-515); they are the majority of the seed and the PR says so.
- **Trade path.** The expert modules write only their own tables; a cluster reaches trading only as a Lane B challenger created by `createChallenger` (trial charged there, KB-042 and the weekly generator cap applied there), after which v1 rules apply unchanged. Arena, agents, picks, cortex and replay never import `src/lib/experts`; a static guard, a write allowlist and the AT-32-style replay hash prove it (D-525).
- **Deferred with reason** (D-510): polling DAT-228, discovery DAT-229, priority wiring DAT-230, extraction LLM-067, budget key LLM-068, UXN-296, the four polling/extraction config keys; the fetch-dependent clauses of AT-39. No LLM call, no network request anywhere in M13-lite ($0, O-64).

## Schema: migration `0022_experts.sql`

Conventions of 0019–0021: STRICT, WITHOUT ROWID where keyed, session dates GLOB, JSON `json_valid`, money integer micro, ratios integer ppm, ISO UTC text. **Every free-text column carries a `length()` cap** and there is no column that could hold an article, transcript or page (PRD-036); the schema test enumerates the TEXT columns and asserts a cap on each and no column named like `body`, `content`, `transcript`, `html`, `raw`.

- `expert`: `id TEXT PK` (`X-nnn`), `name` (≤ 120), `platforms_json` (array of platform ids), `handles_json` (object platform → handle, ≤ 1,000), `home_urls_json` (array of http(s) URLs), `markets_json`, `focus_json` (tags), `licence_status CHECK IN ('unchecked','registered','not_registered','not_applicable')` (seed: `unchecked`, D-520), `status CHECK IN ('candidate','tracked','paused','retired')`, `tier CHECK IN ('core','discovered')`, `no_feed INTEGER CHECK IN (0,1)` (reference authors, D-519), `audience_size INTEGER NULL`, `audience_d NULL`, `poll_json NULL` (DAT-230 settings, unused), `created_at`, `updated_at`. Trigger `expert_guard_update`: abort unless only `status`, `licence_status`, `poll_json`, `updated_at` change; `no_delete`.
- `expert_red_flag`: `id TEXT PK`, `expert_id` (guard: exists), `text` (≤ 400), `source_url NOT NULL` http(s) (D-521: no unsourced flag), `noted_d`, `created_at`; append-only.
- `source_item`: `id TEXT PK` (= `sha256(url + '|' + coalesce(content_hash,''))`), `expert_id`, `url` (≤ 500, http(s)), `platform`, `title` (≤ 200, NULL allowed), `published_at NULL`, `ingested_at`, `content_hash NULL` (64 hex), `summary TEXT NULL CHECK (length ≤ 800)` (80 words checked app-side), `quote TEXT NULL CHECK (length ≤ 160)` (15 words app-side, at most one), `kind CHECK IN ('method','call','market_view','other')`, `extraction_status CHECK IN ('seeded','pending','extracted','failed')`; `UNIQUE (url, content_hash)`; append-only (idempotent on URL plus hash, KB-072).
- `claim`: `id TEXT PK` (seed ids `C-Bn-nnn`), `type CHECK IN ('method','event_link','call','risk_rule')`, `testability CHECK IN ('testable_eod','needs_new_data','needs_intraday','not_testable')`, `cluster_id NULL` (primary cluster; set once from NULL, or moved to the cluster its current cluster was merged into, D-535), `created_at`; the texts live in `claim_revision` so edits are versions: `claim_revision (claim_id, seq) PK`, `statement` (≤ 600), `formalisation_text NULL` (≤ 1,200, prose draft), `vocabulary_gap_text NULL` (≤ 300), `claimed_edge_text NULL` (≤ 400; shown with the label "claimed"), `actor` (`'seed'` or hashed user id), `at`; append-only. Current text = max `seq`.
- `claim_expert (claim_id, expert_id)` and `claim_item (claim_id, item_id)` link tables, append-only, guards: both ends exist.
- `claim_status (claim_id, seq) PK`, `status CHECK IN ('extracted','owner_checked','formalised','screened','challenger','promoted','rejected','parked')`, `reason NULL` (≤ 300), `actor`, `at`; append-only; insert guard enforces the edges of KB-073 (`extracted → owner_checked | rejected | parked`, `owner_checked → formalised | rejected | parked`, `formalised → screened | parked`, `screened → challenger | parked | rejected`, `challenger → promoted | rejected | parked`; `parked → owner_checked`). Current status = max `seq`.
- `cluster`: `id TEXT PK` (`K-nnn`), `name` (≤ 120), `category CHECK IN ('candlesticks','chart_patterns','trend_momentum','mean_reversion','volume','events_news','macro','risk_rules','fundamentals_value','calendar','none')`, `statement` (≤ 600), `canonical_text NULL` (≤ 1,200), `testability` (as claim), `external_grade CHECK IN ('supports','mixed','contradicts','none','not_searched')`, `evidence_links_json` (array of `{ url, note ≤ 120 }`), `vocabulary_gaps INTEGER`, `closest_family NULL` (`F1`…`F6`, `new`, `overlay`), `family_fit_json NULL` (`{ family, params }`, D-514), `created_at`; immutable except through `cluster_state`.
- `cluster_state (cluster_id, seq) PK`, `state CHECK IN ('proposed','confirmed','merged','parked')`, `merged_into NULL`, `reason NULL`, `actor`, `at`; append-only; a `merged` row needs an existing `merged_into` cluster and is final: no later row for that cluster (D-535).
- `claim_cluster (claim_id, cluster_id, role CHECK IN ('supports','contradicts'))` PK, append-only (a claim may support more than one cluster).
- `screening_run`: `run_id TEXT PK` (= `expscreen:<market>:<d>`), `market`, `d`, `q`, `considered`, `eligible`, `screened`, `survivors`, `splits_json` (family → split version), `created_at`; insert-once.
- `screening_result (run_id, cluster_id)` PK, `family`, `params_sha`, `rows`, `blocks`, `mean_net_ppm`, `mean_excess_ppm NULL`, `lower90_ppm NULL`, `p`, `adjusted_p`, `bh_rejected`, `sign_agrees`, `survived`, `rank NULL`, `grade CHECK IN ('L0','L1')`; append-only; guard: run exists.
- `expert_proposal`: `id TEXT PK` (`expprop:<market>:<d>:<cluster_id>`), `market`, `d`, `cluster_id`, `kind CHECK IN ('challenger','new_lineage','f7_lineage')`, `family NULL`, `challenger_id NULL`, `status CHECK IN ('created','exists','refused','parked_build_change','dormant')`, `reason NULL`, `created_at`; append-only.
- `expert_call`: `claim_id PK` (guard: claim of type `call`), `market`, `code`, `direction CHECK IN ('long','short')`, `call_d`, `horizon_sessions`, `target_micro NULL`, `stop_micro NULL`, `tracked INTEGER CHECK IN (0,1)`, `created_at`; append-only. `expert_call_outcome`: `claim_id PK` (guard: call exists and `tracked = 1`), `state CHECK IN ('closed_target','closed_stop','closed_horizon','no_bars')`, `entry_d`, `exit_d`, `net_ppm NULL`, `index_code`, `basis`, `market_ret_ppm NULL`, `vs_market_ppm NULL`, `luck_pct NULL`, `settled_d`; insert-once.
- `source_register` rows (D-522): automated-channel classes `expert_rss`, `expert_youtube_feed`, `expert_own_site` (`permitted_use` 'public feed metadata and own summary only (PRD-036, DAT-227); terms [VERIFY]', `risk 'medium'`, `status 'pending'`, `owner_ref NULL`, `summarisation_permitted 1`); manual-only platforms `expert_x`, `expert_instagram`, `expert_tiktok`, `expert_facebook`, `expert_linkedin` (`permitted_use` 'manual-only: Owner pastes a link, public metadata only (DAT-227)', `risk 'high'`, `status 'disabled'`, `summarisation_permitted 0`). `source_status` rows `mode 'off'`. `+down` lifts and restores the no-delete triggers as 0020 does.
- `+down` drops the sixteen tables. `src/lib/data/schema.ts` `AU_SOURCES` gains the eight ids (the register script checks them).

## Risks (for the PR)

- **Most seed clusters cannot be screened in M13-lite.** Screening needs a cluster expressed as a parameter set of F1–F6 (D-514). The synthesis maps roughly half the clusters to a v1 family by intent, but a parameter-only fit is stricter; the expected count with a valid `family_fit` is small (recorded as a number in the exit evidence). Everything else is stored and shown as "parked: needs a new lineage (build change)". The spec's "robust strategy from all experts" (F7) therefore waits for a structural-rule engine, which is a later Owner-approved build change.
- **Nothing is screened until the Owner confirms claims** (LLM-069, D-512). Staging shows the directory, techniques and a full queue; screening results stay empty until confirmations. 350 claims is a long queue; bulk confirm per expert is the relief.
- **Weekly cap interplay.** Expert proposals go through `createChallenger`, which also applies the per-week generator cap and KB-042. A week in which the v1 generator used the cap yields `refused:weekly_cap` proposal rows; the stage runs last so v1 keeps priority (D-517). The Owner may see "refused" rows for a while.
- **Named people in a private database.** Red flags and licence status are stored only with a source link and date; the public repo holds no name; KB documents omit red-flag text; licence status is `unchecked` for every seed expert until a person checks (D-520). Defamation risk is reduced, not zero; the Owner should review the seed red-flag texts in the private folder before import.
- **AT-39 is partial** (D-527) and ch. 14 lists it in the go-live gate; the deferred clauses are listed in the PR.
- **Converter judgement.** The private converter's `family_fit` emissions are hand-checked by the Fable reviewer (PLAN.md); a wrong fit is caught again at run time (`fit.ts`) and parked as `invalid_fit`, never screened.
- **Calls tracking is mostly dormant.** The 28 seed calls are largely on non-AU codes or macro series; `tracked = 1` only for active-universe codes (D-524), so the calls table will show "stored, not tracked" for most.

Stationary block bootstrap with expected block = the lineage's frozen `block_sessions`, replicates = `bootstrap_replications_min`, PRNG `scopedPrng("expscreen:<market>:<d>:<cluster>:<params_sha>")` (identical re-run). One-sided p = (1 + #{centred replicates at or above the observed mean}) / (R + 1), never 0. `lower90` = 10th percentile of the replicates. - **D-595** (WP4 review, replaces the mean-net fallback of D-518/D-593) The tested series is the excess over matched C2 controls and nothing else: a cluster with fewer than `min_trades` development rows that carry a control is skipped as `insufficient_controls` (no result row, claims stay, not in the BH family), exactly as the challengers stage's `pickWinner` drops a candidate without `meanExcess`. A mean-net series tests a different hypothesis (drift of the market, not an edge over it), its lower 90 % bound is not comparable with an excess bound in one ranking (KB-076 ranks "net excess over controls"), and one BH family must hold one kind of p-value. `screening_result.rows` and `blocks` count the controlled rows; `mean_net_ppm` stays the descriptive mean over every closed development row; `mean_excess_ppm` is never NULL for a stored row (the column stays nullable, 0022 is unchanged). `ClusterStat` loses `controls` and `mean` (`meanExcess` is the tested mean). The seed `expscreen:<market>:<d>:<cluster>:<params_sha>` and `created_at = <d>T00:00:00.000Z` keep a rerun bit-identical.
