# M16 design — Blueprint page

Inputs: `docs/M16_requirements.md` (scope SEC-111…113, UXN-297…300, ARC-001…003; AT-57…AT-59; Q1–Q11), spec ch. 18 V2. Decisions continue from M15 (D-359); this milestone uses D-360…D-370.

Roles: Opus orchestrates; Sonnet builds each work package; a Fable reviewer checks WP1 (access) and WP2 (secrets) before they merge, and the integrated milestone at the end.

## Shape

- One committed model `docs/architecture/architecture.json`, generated by `scripts/architecture/generate.mjs` from the code (routes incl. pages and server actions, workflows, migrations, Worker slots, licence register, secret table names, LLM roles, external hosts) plus the hand-kept `docs/architecture/spec_map.yaml` (spec IDs, view membership, optional coordinates). CI fails when the committed copy is stale or incomplete.
- One page `src/app/(app)/blueprint/` visible only to the pinned Owner; everyone else, signed in or not, gets the plain 404. Live status comes from a read-only loader; the diagram is an own SVG renderer (no new dependency); export is a pure `.drawio` / SVG writer behind an audited route.
- Secrets: the model holds names and stores only, never values (SEC-017); a test scans the model and the export for secret-shaped strings.

## Work packages

As in `docs/M16_requirements.md` §"Recommended work packages": WP1 access guard ∥ WP2 model + generator → WP3 CI check ∥ WP4 live status → WP5 page ∥ WP6 export ∥ WP7 spec browser → WP8 invisibility walk + exit evidence. File ownership: WP1 `src/lib/auth/blueprintGuard.ts`, the proxy branch for `/blueprint*`, `src/app/(app)/blueprint/page.tsx` (placeholder), its tests; WP2 `scripts/architecture/**`, `docs/architecture/**`, its tests; later packages own their own new files and touch WP1/WP2 files only through their exports.

## Decisions

D-360…D-370 adopt Q1–Q11 of `docs/M16_requirements.md` as recommended there: v1 chapters, decision log, config reference and the ID index in the spec browser, no V2 chapter bodies (SEC-110, listed for the Owner); the proxy returns 404, not a redirect, for unauthenticated `/blueprint*`; no config key; the generator reads exported constants only (any new constant is data-only); the host rule is every `https://` host literal in non-test source; no diagram library; the model is committed with a `--check` in CI; the pin check is `isOwnerEmail` plus role owner; two routes `GET /api/blueprint/model` and `GET /api/blueprint/export`; the draw.io desktop open is an Owner check at merge; audit events `blueprint.view` and `blueprint.export`.
