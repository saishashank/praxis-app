# M17 design: intraday watch and pick alerts

Inputs: `docs/M17_requirements.md` (ARN-110…115, EML-038…042, AGT-139…144, DAT-238…240, UXN-301…311, VAL-117…119, NFR-041/042, SEC-114, PLT-077; AT-60…AT-65; Q1–Q16), spec ch. 19 V2 (governs), ch. 14/15 V2. Decisions continue from M16 (D-372; D-831 is the renumbered M16 WP1 rework); this milestone uses D-381…D-400. Architect review 2026-10-31 (Fable): changes marked "(review)".

Roles: Opus orchestrates; Sonnet builds each work package; a Fable reviewer checks the packages marked **F** before they merge, and the integrated milestone at the end.

## Shape

- Two streams, never mixed (ARN-110). **Pick alerts**: every surviving V1 pick (`pick` row: limit = `buy_max_micro`, stop = `stop_micro`) is armed through one adapter `armableOrders(db, market, session)`; a pure `evaluateAlert(state, quote, params)` turns delayed quotes into append-only `pick_alert` transitions (armed, hit, cleared). **Intraday watch**: a signed route runs every 30 minutes, joins today's Sentinel items to delayed quotes, applies the deterministic rule (catalyst AND move AND volume AND fresh quote) and the night-pick gates, writes `intraday_candidate`, e-mails "Attention needed", and records each candidate's outcome after the 18:10 run.
- Everything is shadow. All families are in shadow (D-379/D-380), so alerts arm on V1 picks, the Cortex chance shows "Not enough history yet" on every pick, intraday rows are shown "Unrated" and "unvalidated", and `intraday_stream_state` stays `shadow`. The code paths for allowed or live-tested families are built and proven with fixture states only.
- Nothing in M17 places or changes an order, book, ledger or lesson (ARN-111, SEC-114). The only write targets of the new modules are `pick_alert`, `pick_alert_mail`, `intraday_candidate`, `quote_run`, `email_message`/`email_attempt` (through `sendEmail`) and `cortex_ledger_cell` (through `logCell`). (review) The boundary is enforced three ways, see "Order boundary". No LLM import in the new modules (AGT-139).
- Scheduling is two Worker route slots (signed POST to Vercel), no Actions minutes: `quote-poll` every 5 min 10:00–16:00 (arming is its first step, see D-397) and `intraday-scan` every 30 min 10:30–15:30; early close is enforced inside the routes from `src/lib/data/calendar.ts`; outcome and measurement run inside the existing evening chain (D-399).
- $0 (O-64). Delayed quotes from the Yahoo host already accepted under O-26 only, as a **separate register row** `yahoo_delayed` that the Owner must accept before a single request is made (D-398). SEC-110: ZZ codes and synthetic prices only; the "recorded" quote sessions are generated by a fixture generator, never captured.

## Quote source (review)

Facts verified in the repo: the only Yahoo endpoint used anywhere is `https://query1.finance.yahoo.com/v8/finance/chart/<SYMBOL>` (`scripts/fixtures/record-day.mjs`); `src/lib/data/sources/yahoo.ts` parses daily bars only. The batched `v7/finance/quote?symbols=` endpoint has needed a cookie+crumb since 2023 and is not used in the project; the design does **not** rely on it.

- **Endpoint.** One request per code: `GET /v8/finance/chart/<CODE>.AX?interval=1m&range=1d` (same host as `yahoo_eod`, no credentials). The response `meta` carries `regularMarketPrice`, `regularMarketTime` (epoch s), `regularMarketVolume` (cumulative session volume), `chartPreviousClose`/`previousClose`, `tradingPeriods`. `[VERIFY at build]` remains for these field names; the contract test (WP1) fixes them from a synthetic recording that mirrors the shape, and the parser rejects a response missing any of price, time or previous close (quote dropped, counted "rejected").
- **Quote type** (`src/lib/data/quotes/types.ts`): `DelayedQuote = { code; lastMicro: bigint; quoteAt: string (ISO UTC); prevCloseMicro: bigint | null; cumVolume: number | null; halted: boolean | null; fetchedAt: string }`. Prices are micro-AUD like `pick` (bigint), never floats.
- **Fetcher** (`src/lib/data/quotes/fetch.ts`): `fetchDelayedQuotes(deps: { fetch; now }, codes: readonly string[], budget: QuoteBudget): Promise<{ quotes: DelayedQuote[]; requests: number; rejected: number; paused: boolean }>`; concurrency 4, 250 ms spacing per worker, per-call time budget 20 s (inside the route's 28 s / `maxDuration = 30`), `User-Agent` and politeness as the EOD fetch. Any 429/5xx/network error sets `paused: true` and the run ends ("Prices paused"; remaining codes keep no quote and therefore fail freshness).
- **Budget** (`src/lib/data/quotes/budget.ts`): `QuoteBudget = { perRunMax: number; dayMax: number; usedToday: number }`; `quoteRequestsToday(db, market, d)` sums `quote_run.requests`. Per run: scan ≤ `intraday_scan_requests_max` (40), poll ≤ `intraday_codes_max` (150). Per day: `QUOTE_REQUESTS_PER_DAY = 2000` (`// threshold-ok: politeness budget for the unofficial host, D-400`) shared by both streams; the scan narrows at 80 % and stops at 95 % of it (and of the Vercel/Worker meters of `src/lib/usage/meters.ts` `getMeters`), the poll keeps armed picks only above 80 % and stops at 95 %.
- **Which codes get quotes.** The scan never adds a code (DAT-239) and a code without a catalyst can never be a candidate (AGT-141a), so the scan fetches quotes only for `universe(DAT-239) ∩ codes with a Sentinel item today, materiality ≥ 2` (`src/lib/sentinel/todayItems.ts`), tier 1 before tier 2, watch/held after; cut at the run budget; "scan narrowed" when the cut removed tier-2 codes, "scan stopped" at 95 %. This is a pure narrowing of the spec rule, not a change of it. The poll fetches armed picks first, then watch-listed, then held codes, cut at `intraday_codes_max`.
- **Fail-closed.** Missing `cumVolume` → `rel_volume = null` → condition (c) fails (D-382), System Health "volume unavailable". Quote older than 2 × `intraday_refresh_min` → freshness fails; an armed pick is **never** evaluated on a stale quote (no hit, no clear from a stale price). `halted` unknown → treated as not halted for the candidate gate only after the `universe_snapshot.halted` flag and today's halt announcements are checked; for alerts, halted-unknown changes nothing.
- **Owner acceptance.** Migration 0020 seeds `source_register('yahoo_delayed', permitted_use 'personal use only (DAT-124); intraday delayed quotes, chart endpoint per code', rate_limits 'own budget 2000/day, 40 per scan run, 150 per poll tick, concurrency 4', risk 'high', status 'pending', owner_ref 'O-26', 0)` plus `source_status('yahoo_delayed','on')`. `SOURCE_CONTROLS` (`src/lib/data/controls.ts`) gets the third entry with its risk text (O-26 style: unofficial, personal use, may be blocked, much higher request count than end-of-day, kill switch). Until `status = 'enabled'` **and** `source_status.mode = 'on'` **and** `dispatch_enabled`, both routes return `{ status: "skipped", reason: "source_not_accepted" | "source_off" }`, no request is made, no pick is armed, no candidate written; System Health shows the reason. `docs/source-licence-register.md` gets the row; `scripts/ci/licence-register.mjs` must pass.

## Alert delivery (review)

- **Keys and kinds** (`src/lib/email/keys.ts`, `EmailKind` in `src/lib/sentinel/schema.ts`): `pick_hit` → `pickhit:<alert_id>:<d>`, `pick_cleared` → `pickclr:<alert_id>:<d>`, `pick_candidate` → `pickcand:<market>:<d>:<code>`, `pick_batch` → `pickb:<user_id>:<d>:<HHMM>`, `pick_digest` → `pickdg:<user_id>:<d>`. All five take only the `pool` slot in `slotCandidates` (never `p0`, never `reserved_*`), so the P0 slot and the reserved review/incident/reminder slots are untouched by construction.
- **Idempotency.** State first, mail second: the `hit`/`cleared` transition row is inserted (unique `(alert_id, seq)`), then `claimKey` with the key above; `exists` → no second mail across Worker re-posts, Vercel retries or two ticks evaluating the same quote. One `hit` mail per pick per session is the key's `<d>`.
- **Own daily cap** (`src/lib/email/pickMail.ts` `pickCapRemaining(db, env, d)`): `pick_alert_emails_per_day` (12) minus the day's counted `email_message` rows of the five kinds; candidates additionally against `intraday_candidate_emails_per_day` (3). Exhausted → `recordRow(... 'suppressed_cap')` and a `pick_alert_mail` row `suppressed_cap`; the item shows in "My alerts", "Needs you" (candidates) and Evening Review section 9. The cap test asserts `pick_alert_emails_per_day ≤ email_daily_cap − email_reserved_slots − p0_email_daily_cap` is **not** required (pool is shared) but that a full pick cap never blocks a P0 claim (P0 uses its own slot).
- **Batching.** The poll tick is the 5-minute window: all hits/clears of one user found in one tick go out as one `pick_batch` mail listing the codes (EML-020 style); a single one goes as `pick_hit`/`pick_cleared`. Candidates found in one scan run for one user → one mail per run.
- **Quiet hours.** `getQuietHours(db, userId)`, `inQuietHours(now, q)` (`src/lib/alerts/api.ts`, Melbourne minutes). Inside quiet hours the mail is not claimed; a `pick_alert_mail` row `held` is written. The first `quote-poll` tick after the window ends sends one `pick_digest`; if the window ends after the last tick (16:00), the held rows become `held_to_review` and are listed in that evening's Review section 9 (no separate mail) — D-388 refined. Nothing here is P0; P0 handling in `src/lib/alerts/flush.ts` is not touched.
- **Staging** sends none: `emailEnvName` ≠ production → `suppressed_off` as today.
- **Time zones.** Worker slot times are `Australia/Sydney` local (`worker/src/localtime.ts` `sydneyLocal`; Sydney and Melbourne share AEST/AEDT so the spec's "Melbourne" is identical); session date = `marketDate(now, tz)` from the calendar; e-mail dates `melbourneDate`; quiet hours `melbourneMinute`. The TST-103 DST cases are re-run for 10:00/16:00/10:30/15:30 and the early-close end (WP5 tests).

## Slots and budget (review)

Both slots: `runner: "route"`, `workflow: null`, `tradingDaysOnly: true`, `marketBound: true`, `catchUpMin: 0`, `enabled: true`, `requiresListing: true` (D-387). Recurring route slots post once per matching minute with no state; the routes are idempotent per `(market, session, slot_minute, purpose)` through `quote_run` (insert-once; a second POST returns `already_done`).

| id | time | until | everyMin | route | priority | extra |
|---|---|---|---|---|---|---|
| `quote-poll` | 10:00 | 16:00 | 5 | `/api/internal/pick-alerts` | 5 | — |
| `intraday-scan` | 10:30 | 15:30 | 30 | `/api/internal/intraday-scan` | 6 | — |

Early close: the route reads `sessionTimes(d, rows, hours)` and returns `skipped: after_close` past the close; the Worker schedule stays static. Daily cost: ≤ 73 + 11 = 84 signed posts and Vercel invocations (each ≤ 28 s), 0 Actions minutes, ≤ 12 Resend sends. `pick-arm` as a separate slot is dropped (D-397); outcome and measurement need no slot (D-399).

## Cortex hand-over (review)

`src/lib/cortex/night.ts` is **not edited** (`runNight` inputs unchanged, replay hash unchanged by construction). The hand-over is a read-after-run: `src/lib/intraday/outcome.ts` `recordOutcomes(db, market, d)` maps each `intraday_candidate` of session `d`: code in `pick` rows of `d` → `night_pick`; else in `decisionsForNight` with a blocking gate → `rejected:<gate>`; else scored but not taken → `rejected:rank`; code absent from the `universe_snapshot` tiers the families use (`FamilyNightRule.tiers`) → `not_in_universe`. Candidate codes are already evaluated by the run when they are in the universe (AGT-144 "exactly as any other code"), so no input injection is needed; AT-61(d) asserts an outcome for every candidate after a synthetic run, AT-61(e) the identical hash. Called from the evening-review route handler before the sections build (idempotent; one added call, D-399).

UXN-308/309 (`src/lib/picks/chance.ts`): `chanceDisplay(x: { status: FamilyStatus | "live-tested"; p: number | null; lo: number | null; hi: number | null; nEff: number | null; slopeUb: number | null; hideBelow: number }) → { kind: "chance"; pct; lo; hi; n } | { kind: "no_history" }`; `hideBelow` is read from `cortex_slope_hide_ub` (1.0, D-257/D-390). With every family shadow it returns `no_history` for every live row; the six fixture combinations prove the path. `sortPicks(picks, basis)` keeps V1 `rank` order for no-chance picks. No Cortex `p` reaches alerts: `evaluateAlert` takes `{ limitMicro, stopMicro, state }` only and `src/lib/alerts/pick/**` has no cortex import (import guard).
