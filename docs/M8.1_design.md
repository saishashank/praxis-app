**D-207 — M8.1 open points (spec defaults taken; listed in the V2 PR).**
1. GL-01: a price-only inferred split/consolidation never auto-applies, also not after the 5-session rule; it stays in the Owner queue and blocks entries on that code until resolved. The 5-session rule stays for conflicting announcement/vendor readings. Vendor split rows (DAT-231) and a Yahoo adjusted-close ratio that disagrees act as a veto.
2. GL-02: nullable `known_at` on the confirmed action/factor, set at first confirmation; rows from the 2020–26 history backfill take `known_at = ex_date` (otherwise every old split would be invisible to replays). Replays and the decision view use only factors with `known_at` ≤ the decision cut-off of D.
3. GL-03: fill quantity = largest affordable whole parcel at the actual open that is ≥ one marketable parcel (A$500 floor); cancel as `cash` only when one marketable parcel is unaffordable. Replay uses the same function.
4. GL-04: `adj_close` is optional; a null never rejects a bar; when present it is validated as before.
5. GL-05: batch 2b waits up to 4 min for the "first completed poll after 18:10" marker (the `decision-cutoff` slot is enabled), then proceeds and records `cutoff_poll_missing` on the run record. Backfilled rows store `first_ingested_at`; replays drop rows whose `first_ingested_at` is after the cut-off.
6. GL-06: a `dispatch-failed` run record carries the HTTP status; 401/403 raises an S2 incident the same night.
7. GL-07: watchdog and the Batch-1 fallback get their own schedule lines for both DST offsets (generated by `genWatchdogCron.mjs`, O-52).
8. GL-08: Evening Review footer adds the SEC-016 sentence.
9. GL-09: the release gate fails when the fixtures checkout or any fixtures-dependent test was skipped on a release PR (ZAP already fails on skip). Switching the gate to full mode stays an M8 close-out item (noted in the PR).
10. GL-10 (O-51): dividends stay credited; the M6/M8 register lines are corrected; comparisons use a total-return benchmark (index plus dividends reinvested on ex-date from vendor rows) — labelled "Price only" until vendor dividends cover the window.
11. LLM-070: a roster module with `checked_on` dates; providers whose pages cannot be read are `unverified`; roles stay rules-only until a bake-off passes (D-177).
12. DAT-231: the nightly Yahoo fetch requests actions in the same call and stores vendor split/dividend rows; no extra request.
13. D-170 (wide pages, glow) and D-174 (read-only Configuration) were later Owner requests and stand: UXR-012's 1,120 px column and UXR-009's "no shadows" give way to D-170; UXR-028 keeps list, current value, default and the "changed" dot, without an editor.
14. Settings rows open a Sheet (bottom sheet on phones, 480 px drawer on desktop) built on the existing Radix dialog; without JS the row links to its detail page.
15. High contrast keeps the hues at AAA with two-letter marks and patterns; effects stay off there (D-170). The eight family-colour tokens are defined now (used by M17 badges).
