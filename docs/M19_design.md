## Shape

- **One profile, one reader, one seed (MKT-107, DAT-241, D-925).** `src/lib/market/` is the only place a market fact is written down: a plain-ESM core (`profileCore.mjs`, importable by the Worker and the Actions scripts like `calendarCore.mjs`), the typed loader (`profile.ts`), the seed modules (`seed/AU.mjs`, `seed/IN.mjs`, `seed/US.mjs`) and the write guard (`guard.mjs`). Everything else asks the loader. Migration `0034_m19_market_profile.sql` stores the seed; migration `0035_m19_market_guard.sql` installs the write guard (D-992, D-995).
- **AU is byte-identical (CXA-001, A-20).** Three proofs, all taken **before** the first M19 merge (integration step 0) and re-run at exit: the AT-32 and AT-50 replay hashes (stored baseline, D-1007), the AU constants snapshot (every AU constant the refactor removes, captured by name and value, asserted equal to `loadProfile("AU")` afterwards), and the Worker's AU slot-minute table (snapshot). "Any difference is a defect, not a tuning."
- **Off in production is three proofs, in code (MKT-110, D-926).** (a) the Worker clock builds its slot table per **enabled** market from the `market` table and refuses `runNow` for any other; every script with a market input calls `assertMarketEnabled` before its first write; (b) a `BEFORE INSERT` trigger on every data table with a `market` column refuses a row of a market that is not enabled (`MarketNotEnabled`), the app maps the error and logs an incident, and the M18 nightly invariant (D-960) now alarms on rows of any **not-enabled** market; (c) loaders, routes, e-mails and the switcher list enabled markets only, any market parameter outside that set is `notFound()`, and the only IN/US words a production page can render are the Owner's Markets row. Production stays `markets_enabled = ["AU"]` for all of V3 (BLD-050): the migration seeds `enabled = 1` for AU only, and AT-68 runs in every CI job.
- **Two switches, the stricter wins (gap 9, D-994).** `enabled` (the `markets_enabled` set, production `["AU"]`) and `mode` (`off | data_only | full`) are both kept. A job runs only when enabled **and** mode ≠ off; a row is written only when enabled; UI shows only enabled. A row-level `CHECK (enabled = 1 OR mode = 'off')` makes the inconsistent state impossible to store.
- **Built, not complete (gaps 4, 7, 17; D-998, D-999, D-1001).** IN and US get their profile rows in M19 with work status `built` and every spec [VERIFY] value seeded with `verify = 1` and no `verified_at`, so `complete` is false by construction until M20 records the evidence. Nothing in M19 reads an IN or US value on any production path.
- **Turso at the 20 % line (PRD-045).** The seed is ~110 rows once; the guard trigger costs one primary-key probe of the 3-row `market` table per inserted row (`rows-ok: 1 per insert`); the Worker keeps its one `market` read per tick (now `WHERE enabled = 1`, ≤ 3 rows); the loader caches per process; no new list query, no `OFFSET`.
- **No staging, ASX off, $0, no secrets.** Verification is CI (the recorded-day job in the production shape, AT-68 in the `app` job) plus the read-only production checks in the evidence; `worker/src/asx/*` changes only where a literal is removed (PRD-047; `ASX_LIVE !== "1"` → skip stays); no new provider, key or env secret (`PRAXIS_MARKETS_ENABLED` is a plain variable, not a secret).

### MKT-110 (b) No rows
- **Current state (verified).** No write guard exists; writes go straight to `@libsql/client` (`src/lib/db/client.ts:27` `mainDb()`, the scripts' own `createClient` calls, the Worker's `pipeline()` in `worker/src/db.ts:49`). ## Risks and spec findings

- **73 vs 80 files (A-19, gap 1).** The spec's count used another rule or an older tree; D-991 records the scripted rule and 80. Listed.
- **`CALENDAR_MARKETS` is in `calendar.ts`, not `calendarAdmin.ts` (gap 2).** The admin module re-exports it; D-993 derives it from `CALENDAR_RULE_MODULES`, which is already keyed by market. Spec example corrected in the evidence.
- **"No IN/US row in Turso" versus the profile rows (MKT-110 b, DAT-241).** The IN/US `market`, `market_profile` and `market_profile_field` rows are configuration and must exist in production for the Owner's Markets row; "no row" is read as "no data row" (every table with a `market` column, the D-960 list). `trading_calendar` is in that list: M20 must decide whether IN/US calendar rows (DAT-248: "seeded at M20") are configuration — if they are seeded in production the invariant and the guard need an exemption then, not now. Listed.
- **Decision numbering slip (gap, D-1005).** The extract and BLD-054 say M19 starts at D-951; M18 used D-951…D-990. M19 uses D-991 onwards; the index generator refuses a duplicate id (R4-I1), so the slip could not have passed CI.
- **`markets_enabled` is "E" in ch. 15 but the M20 two-step changes it from the UI.** D-994 keeps the DB column as the run-time truth and the environment variable as the production assertion (nightly mismatch alarm); after a switch-on the Owner also sets the variable (an M20 PR line). Listed.
- **Guard triggers on 91 tables** (the 92 with a `market` column minus `market_row_count`). One primary-key probe per inserted row; the full price backfill (cap 2 M rows per month) would add at most 2 M reads (2 % of the budget) in a backfill month, ~15 k on a normal night. Measured in the evidence. An upsert (`INSERT … ON CONFLICT`) fires the `BEFORE INSERT` trigger once per row as any insert does; the `BEFORE UPDATE OF market` trigger never fires on AU rows that keep their market.
- **`INSERT OR IGNORE` is refused, not ignored.** `RAISE(ABORT)` in a trigger overrides the conflict clause; this is the wanted behaviour (a refused write is loud), tested.
- **Test fixtures that plant off-market rows** (`rowsByMarket.test.ts` and any M20 test) must use `plantOffMarketRow`; a direct insert now throws. Recorded in `tests/db/helpers.ts`.
- **Worker local time for non-AU zones is a stub (D-1004).** Unreachable in M19 (only AU is enabled); M20 adds the tables with DST tests. The `localtime.ts` CPU budget (PLT-070) is unchanged for AU.
- **The e2e `leaks()` word list.** `IN` and `US` as bare words cannot be searched in English text; the walk relies on `data-market` attributes plus exchange, city and currency words. A page that names a built-off market in free text without the attribute would pass the walk — the Owner-row-only rule is therefore also enforced in the loaders (D-997: nothing but the Markets table reads a not-enabled profile), tested in `tests/ui/loaders/switcher.test.ts` and `tests/settings/region.test.ts`.
- **Currency labels on money keys.** `ledger_notional_aud`, `picks_portfolio_seed_aud` and `profile_portfolio_amount` keep their names (renaming would be a config migration with no benefit) and their numbers; only the display unit changes to the profile's symbol. Listed under D-1003.
- **Post-deploy full replay runs** (`replay-needed.mjs`, D-917) because the migrations touch replay tables and `src/lib/config/` changes: this is the production AT-32 proof, and it costs one replay's reads (already budgeted in D-905).
- **No Owner prompt.** Every [VERIFY] of IN/US stays `verify = 1` in the seed (D-999) and nothing reads it; every M20 reader is a tested `not built (M20)` stub (PRD-039); the three off-in-production proofs ship on by construction (the seed), never behind a flag the Owner must set.
