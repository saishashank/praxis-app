## 5.1 Concepts
| Term | Meaning |
|---|---|
| Execution | One of the 12 live paper accounts of a market (E01–E12): family + variant (U / L) + rule version + cost profile, seeded with the market seed (AU **A$600**). |
| Family | Strategy idea F1–F6 (rules: Ch. 07 §7.4). A rule version applies to **both** twins of the family. |
| Twin pair | U and L executions of one family: identical signals; live cohorts start together (ARN-053). |
| Cohort | One run of an execution from a start session with the seed until a terminal state. |
| Terminal states | Evaluated at session closes on **liquidation NAV** = NAV − estimated exit costs of all open positions and the sleeve (brokerage + ARN-032 slippage). **Target** liquidation NAV ≥ 2× seed (A$1,200); **Bust** ≤ 50% of seed (A$300); **Stalled** no open position and either (a) NAV < `stall_floor` for 5 consecutive sessions, where `stall_floor` = parcel + entry brokerage + entry slippage at 10 bps + buffer (1% of NAV) ≈ A$500 + 5 + 0.5 + 5.1 ≈ **A$511 for U and L alike** (the sleeve is optional, ARN-003), or (b) over 20 consecutive sessions there was **at least one** family signal and **every** signal was rejected only for parcel/whole-share reasons; **Timeout** 252 sessions. "Resolved" = any terminal state; "censored" = not yet resolved. The realised value after the actual next-open liquidation is also stored and shown. |
| Controls | C1–C3 baselines (ARN-004). |
| Lineage | A family's tree of rule versions from its v1 rules, including all challengers derived from it; split dates, purge and trial budget are per lineage. |
| TTD | Time-to-target: sessions (and calendar days) from cohort start to the close at which **liquidation NAV** first reaches the target. |
| Sleeve | Hypothetical leveraged side-account of an L execution (§5.6). |
| Decision cut-off | Fixed wall-clock time per market (AU **18:10 Melbourne**, config) of session D. Inputs with `published_at` (or `ingested_at` when unknown) before it may be used for decisions made after D's close; later inputs belong to D+1 — **regardless of when the batch actually starts**. |

## 5.2 Arena composition

- **ARN-001** 12 live executions per market, each seeded with the market seed (AU A$600 [OWNER O-25]), all aggressive [OWNER], one shared data feed and cost/slippage model.
- **ARN-002** Composition 6 families × {U, L} [OWNER O-18]: E01/E02 F1 Trend; E03/E04 F2 Quality-value with catalyst; E05/E06 F3 Event drift; E07/E08 F4 Mean reversion; E09/E10 F5 Small/mid-cap discovery (E10 sleeve eligible on U2 entries); E11/E12 F6 Consensus.
- **ARN-003 (s9)** At most 2 open positions; a second only if both can each meet the marketable parcel after costs (ARN-024). If the stock entry and a sleeve opening can't both be funded, **the sleeve is skipped**, never the stock entry. Every position has an initial stop and a time stop.
- **ARN-004 (s9) Controls** (per market):
  - **C1** buy-and-hold of the broad index ETF (AU: S&P/ASX 200 ETF [VERIFY code]) run as cohorts with the same seed and terminal rules; reported mainly by E[NAV at end] − seed and drawdown (it will usually time out).
  - **C2** matched random-entry controls **per family**: for each actual family entry (live or replay), a control entry on the **same session** in a **random eligible code** (excluding the signal's own code and any code with a same-day qualifying signal or event for that family) of the same tier and the same 20-session volatility decile (passing the same filters), sized the same way, with the same costs and slippage, exited **mechanically by the family's exit rules mapped to the control**: price-level rules anchored on an event (event-day low, F3 initial stop, F2 close-below-event-low) become the **same distance in ATR(20) units measured from the control's entry session** (e.g. an event low 1.3 ATR below the entry-day open → control stop 1.3 ATR below its own entry-day open); indicator/time rules apply unchanged; event-dependent exits that cannot be mapped (thesis-breakers, F6 "earliest exit of any contributing family") are replaced by the family's time stop; the mapping table is a known-answer test (TST-101). A control that holds a position or cannot afford the parcel **skips** that entry; the skip rate is reported. Live display: 20 C2 portfolios per family. Tests use `c2_controls_per_row` matched controls per signal-ledger row (default 20) from a shared precomputed path library and the bootstrap of ARN-081. **(s11)** C2 controls have an exit-mapping bias for event families (ARN-004 event-family exits are replaced by time stops) which is disclosed in the validation label: event-family PASSED-BACKTEST / CONSISTENT-FORWARD labels carry the qualifier "C2 exit-mapping bias (ARN-004)" **(s11)**.
  - **C3** the same C2 entries with a sleeve attached under the same sleeve rules; 20 per family live.
  - Controls start new cohorts together with their family's twins (ARN-053); an unfinished control cohort is **continued in shadow** to its own terminal state exactly like a twin.
- **ARN-005** ≤ 8 unfunded challengers concurrently per market (KB-042).
- **ARN-006** Lower-risk tiers may be added later by configuration.

- **ARN-014** If the universe cannot be refreshed, the last good list is used and flagged.

## 5.4 Timing and execution
- **ARN-020 (s9) Decisions and day 0.** Decisions for session D use only inputs before D's decision cut-off (§5.1) and fill at D+1's open. **Day 0** of an event = the session during which it was published, or the next session if published after that session's continuous trading ended (or on a non-trading day). An event published after the close of D but before the cut-off has day 0 = D+1 and cannot drive a D+1 order (its day-0 bar doesn't exist yet). Backfilled historical items without an exact time are labelled "assumed time" and given **session-level** timing: day 0 = the announcement date if it is a trading day (else the next), usable from that day's cut-off; because intraday position is unknown, the primary validation statistic **excludes** untimed events and a sensitivity result including them is shown beside it (ARN-082).
- **ARN-020a (s9) Pre-open re-check.** At 09:55 exchange time a signed Vercel route (invoked by the Worker) re-checks each pending buy against halts/suspensions, ARN-011 and thesis-breakers using items published since the order was created; failing buys are cancelled (reason on the Decision Card). It never creates orders and never exits held positions (held-position thesis-breaker hits found pre-open become exits via the normal nightly cycle, i.e. filled at the following session's open). If the re-check hasn't run by 10:00, pending orders fill and are flagged "not re-checked". Replays apply the same rule using historical timestamps. **(s13)** The route uses the PLT-012 timeout; on timeout or error the Worker retries once at 09:58, then raises a P1 alert and orders fill flagged 'not re-checked'. When the ASX source is off, the halt proxy (DAT-127) applies: a pending buy for a code with zero volume or no price in the last session is cancelled with reason 'possible halt — ASX feed off'.
- **ARN-021 (s9) Exit types and fills.** Exits are tagged `intraday_stop` (IS) or `close_signal` (CS):
  - IS levels (initial, ATR, trailing, sleeve close-out) are in **raw prices**, re-based at corporate actions, recomputed at each close and active from the next session; the **initial stop is computed from the actual entry fill price** and is active from the entry session after the open.
  - IS fill: if the session **opens at or below** the level → fill at open − slippage; otherwise, if the low reaches the level → fill at level − slippage − 1 tick.
  - CS exits are evaluated at the close and filled at the next open − slippage.
  - If a stop and a close signal both apply, the earlier fill wins; ambiguous intrabar ordering assumes the worse outcome.
- **ARN-022** Long-only cash equities/ETFs; leverage only in the sleeve.
- **ARN-023** Whole shares only (rounded down).
- **ARN-024** A buy opening a new holding must be ≥ `min_marketable_parcel` (AU A$500 [VERIFY]); participation cap 1% of 20-session ADV; buys that fail are rejected and logged.
- **ARN-024a** Deployable cash = settled/matched cash − sleeve margin to be moved if a sleeve opens (only when both fit, ARN-003) − estimated brokerage − buffer (1% of NAV). Shares = floor(deployable ÷ expected fill price), where the expected fill price already includes ARN-032 slippage (slippage is not reserved a second time). **(s13)** Estimated brokerage for sizing = the cost-profile charge for an order worth the whole deployable amount (conservative because P5 is non-decreasing in order value); after the share count is set, actual brokerage is recomputed on the real order value. No iteration.
- **ARN-025** Settlement default `matched` (T+2 AU); variant `conservative`.
- **ARN-026 (s9)** Halts/suspensions: no fills; frozen at last price; after 20 sessions marked at the suspension haircut (default 50%). Delisting at last price, except administration/liquidation → 0 unless a distribution is announced. If a cohort ends holding a suspended position, that position is moved at its current (haircut) value to a **legacy ledger** of the ended cohort and settled there when it resumes or is delisted; the new cohort starts clean.
- **ARN-027** Trading calendar per market.

## 5.6 Leverage sleeve (simulated owner experiment)
- **ARN-040** L executions carry a sleeve: margin = min(A$20, 4% of NAV) [OWNER]; leverage 10× [OWNER, hypothetical]; one sleeve trade at a time; no compounding.
- **ARN-041 (s9) Margin model.** When a sleeve trade opens, the margin is **moved out of cash** into a separate sleeve-margin balance; it returns to cash (plus or minus sleeve P/L and costs) when the sleeve closes.
- **ARN-042** The sleeve opens only with its family's entry and closes at the same exit; underlying must be U1 or an index ETF (E10: U2 too); never U3. Ineligible days are logged.
- **ARN-043** Sleeve price P/L = margin × leverage × underlying return between the sleeve's entry and exit fills. **(s11)** Splits and consolidations do not change sleeve notional or margin; the underlying-return series used for sleeve P/L is adjusted via the recorded adjustment factor (DAT-220), and stops are re-based identically to the raw-price stop re-basing rule (ARN-021).
- **ARN-044** Close-out when price P/L + accrued financing reaches −50% of the margin (IS exit); price P/L + financing loss capped at the margin; brokerage and slippage charged in addition.
- **ARN-045** Sleeve costs: brokerage on notional per `sleeve_cost_profile` (default the execution's profile: P5 A$5 per side), slippage per ARN-032, financing 9% p.a. on exposure per calendar day [VERIFY]. The app shows the **break-even move** (≈ +5% at A$200 exposure under P5) beside the **close-out move** (≈ −5%), stating that they are about equal.
- **ARN-046** A losing sleeve trade locks the sleeve and records `loss_to_recover`.
- **ARN-047 (s9) Recovery modes** (named REC-1…REC-4 to avoid confusion with LLM roles): **REC-2 (default)** unlocks when unlevered realised net P/L since the lock ≥ `loss_to_recover`; REC-1 when NAV at a close ≥ NAV at the close before the losing sleeve trade opened; REC-3 when the shadow sleeve (ARN-048) has earned ≥ `loss_to_recover`; REC-4 after 10 sessions. A new cohort resets to unlocked.
- **ARN-048** A shadow sleeve logs hypothetical trades while locked.
- **ARN-049** Sleeve figures shown at 10× and at the reality-adjusted 5× (ASIC retail CFD cap on shares; order to 23 May 2027 — re-verify after, OPS-020), labelled "hypothetical leverage"; market-specific.
- **ARN-050** Sleeve metrics: trades, win rate, net expectancy, close-outs, gross/net P/L, costs, financing, lock episodes, utilisation, paired effect vs the U twin.

## 5.7 Cohorts and NAV
- **ARN-051 (s9) NAV** at each close = cash (settled + unsettled receivables − unsettled payables) + Σ(quantity × raw close, or haircut value) + dividends receivable + sleeve-margin balance + sleeve unrealised price P/L − accrued unpaid financing. Franking excluded. **TTD** = sessions from cohort start to the first close with **liquidation NAV** ≥ target (§5.1).
- **ARN-052** Bust, target and stall are judged on liquidation NAV at a close (§5.1).
- **ARN-053 (s9) Cohort end and restart.** At a terminal close the outcome and TTD are fixed; positions and the sleeve are closed at the next open under normal fill rules (suspended positions → legacy ledger, ARN-026); the next cohort starts at the open after that. **Twins restart together live:** when one twin resolves, the other's live cohort is liquidated the same way and both restart on the same session; for **statistics** the unfinished twin's (and each control's) cohort is **continued in shadow** (same rules, no live effect) until its own terminal state, so no informative censoring is introduced. Replays run each twin's cohorts on the same start grid and use the same shadow-continuation rule. Controls follow the same rule. Shadow cohorts overlap live ones in time, so cohort counts use **effective N** — the **single definition used everywhere** — = the number of resolved cohorts that do not overlap in time with an already-counted cohort (greedy in start order over the cohorts' actual outcome intervals — a live cohort that overlaps its own twin's shadow cohort may not count; the app shows effective N per execution), never raw counts. Cohort-level intervals are computed on those non-overlapping cohorts only (exact / Aalen–Johansen), shown with effective N. Ledgers are separate per cohort; the sleeve lock resets.
- **ARN-054** Further target rungs may be recorded; termination at rung 1 is the default.

## 5.8 Daily learning loop
- **ARN-060** **Close the books** in batch 2 before signals: apply D's opening fills and IS exits from D's bars → corporate actions, dividends, financing → settle and mark to market → ledger invariants → terminal and sleeve-lock checks.
- **ARN-061** Attribution tags for every trade and position (family, execution, rule version, tier, signals/agents, regime, events, holding period, costs, slippage, MFE/MAE, exit reason, filter decisions); blocked trades and their later outcomes.
- **ARN-062 (s9)** Nightly comparisons (paired twins, families, tiers, filters, cost profiles, event vs technical, regimes) are **descriptive** (point estimates with 90% intervals, labelled "descriptive — not a finding"). **Findings** ("E03 did better than E05") come only from the **weekly** test run with block-bootstrap intervals and Benjamini–Hochberg control across that week's comparisons; a detected difference gets **exactly one confirmation look** on new data once it holds ≥ 30 rows and ≥ max(75, 15 × block) sessions (the date is shown), one-sided α = 0.05 with the ARN-081 bootstrap; for comparisons (weekly tests and the look) the block is the **larger frozen block of the lineages involved**; if it fails it is discarded and that comparison cannot be re-detected for 60 sessions; otherwise "no detectable difference (n = …)". Single-day results are labelled "single-day result — noise".
- **ARN-063 (s9) Lesson grades (single definition):** **L0** Observation; **L1** Hypothesis — ≥ 30 relevant trades and a 90% interval excluding zero on the **first two-thirds of (development − one purge)** (fixed in advance; lessons are generated only from this part); **L2** Tested — holds on the **last third of (development − one purge)**, with the purge between the two parts (never used to generate lessons), n ≥ 30 relevant rows (else "L2 not reachable" with its date), under **cumulative** false-discovery control over all L2 tests ever run on that window (Foster–Stine α-investing: initial wealth W₀ = 0.10; test j uses level α_j = W/(2 + W), costing α_j/(1 − α_j) = W/2; a rejection earns 0.05; wealth is **carried forward** across rolls, never reset; one wealth pool per lineage, and one market-level pool for cross-family lessons; target mFDR ≤ 0.10); cross-family lessons use the earliest split dates of the lineages involved; lessons **never** access the validation or holdout splits and so do not consume the trial budget (ARN-085); **L3** Adopted — an L2 lesson applied via Lane A, or one that motivated a challenger which then passed VAL-110. Lane-A "unproven notes" from L0/L1 keep their grade and never become L3.

## 5.10 Validation (walk-forward, trade-level evidence)
- **ARN-080 (s9) Replays.** Cohort replays start every 5 sessions (descriptive CIFs with effective N per ARN-053). **Trade-level evidence** uses the **signal ledger**: every family signal that passes filters, de-duplicated so that each (family, rule version, code) has **at most one open row at a time**: a new row may start only after the previous row's exit, applying the **live** re-entry rule and its current `reentry_block` parameter (FAM-002: block after a stop exit), and event families create **at most one row per event**; simulated **unconstrained at fixed notional** (A$600, no position limit, no cash interaction) with its matched C2 control(s). A secondary **capacity-constrained book** (top-ranked, ≤ 2 positions, as live) with its own C2 controls is reported on the development split only. Replays need 1,260 benchmark sessions of warm-up for the regime classifier before the first decision.
- **ARN-081 (s9) Primary evidence is trade-level.** Statistic: mean paired excess e = (row net return − matched control net return) over signal-ledger rows, **studentised** = (mean excess) ÷ (block-bootstrap standard error of centred excesses). **(s11)** The block-bootstrap standard error is the SD of the bootstrap distribution of the mean centred excess across B replications, each computed on a random sample of blocks drawn with replacement. Null distribution: **circular block bootstrap over entry dates** with block length = max(5 sessions, the 75th percentile of the lineage's realised holding period), measured and frozen per lineage as in ARN-082 (not recomputed between rolls) applied to the centred excesses (e − ē) — the **only** bootstrap procedure for trade-level tests (VAL-110 (i) and (ii), ARN-084, ARN-062, AT-17); one-sided. A tested window must contain **≥ 15 blocks**; otherwise the result is "insufficient independent blocks" with the date it becomes reachable. Multiple testing: **Bonferroni over the trial budget** (ARN-085; default m = 20, α_i = 0.0025) and **Bonferroni across the market's active lineages** (L = max(6, number of active lineages); α_i ÷ L ≈ 0.00042 with 6; Holm step-down only when all are tested in one run). Bootstrap replications B = max(1,000, 20 ÷ level used) (≈ 48,000 at α_i ÷ 6); matched controls per row = `c2_controls_per_row` (default 20). AT-17 checks test size at 0.05 and 0.01 (binomial acceptance bounds plus a uniformity check of the lower-tail p-values; reduced B allowed only for these checks); size at the smaller levels actually used is extrapolated and stated as such. Every result shows the **minimum detectable effect** (80% power at the level used). **Absolute gate:** the rows' own mean net return must also be > 0 with its one-sided 90% lower bound > 0 under P5 (brokerage cancels in the paired excess, so the excess alone cannot show profitability).
- **ARN-082 (s9) Splits (frozen dates, rolling holdout).** For each lineage the split dates are fixed in a versioned record when the lineage is created: **holdout** = entries in the most recent holdout-length window of history that ends **one completion window before the data end** (the completion window lies inside history, so outcomes are complete; the resulting first-usable date is shown); **validation** = entries in the validation-length window before it; **development** = everything earlier. Splits are defined by **entry dates**; purge between splits = the **upper bound of the lineage's maximum-holding-period parameter** (Ch. 15 bounds) + 20 sessions, frozen per lineage, so no trade — including a challenger's — crosses into the next split and each trade keeps its **full** outcome; the completion window after a holdout has the same length. **Window lengths are frozen per lineage** as holdout = max(378, 15 × block) and validation = max(504, 15 × block) sessions, where block is the ARN-081 block length **measured once**, on the data before the default 378/504 layout (i.e. before the default validation window's purge), and **frozen together with the window lengths**; both are re-measured only at a roll. If the resulting development split would be < 252 sessions, the lineage's splits are deferred and the date they become possible is shown — so the ≥ 15-block rule can always be met by waiting, and every reachable-date formula (F5 coverage, DAT-130/170, VAL-102, forward labels) uses these lengths. Minimum evidence: ≥ 100 signal-ledger trades and ≥ 15 blocks in the tested window; otherwise "insufficient evidence" with its computed date. The holdout is used **once** per rule version. **Rolling holdout (lineage-level event):** a roll happens when a challenger of the lineage is **promoted**, or when the Owner requests it after at least one holdout-length of new data. At a roll: the new holdout = entries after **max(the promoted version's registration date, the promotion date)** + one purge (usable once holdout-length + completion window has passed); validation = the validation-length window ending one purge before the new holdout; everything earlier becomes **development** (which therefore grows); lesson thirds (ARN-063) are re-frozen. Between rolls every challenger of the lineage is tested on the lineage's **current frozen validation window**, and a not-yet-promoted challenger's holdout confirmation uses entries after max(its registration date, the Owner's last view of its forward shadow results) + one purge (forward data displayed before registration is never its holdout). VAL-110 and holdout confirmations use **only rows whose outcome is fully observed** (entry ≥ one purge before the test date); the earliest possible test date is shown. After a promotion the promoted version's holdout **is** the lineage's new holdout, both defined as entries after max(registration, promotion date) + one purge (one definition, so rows shown to the Owner before approval are never holdout rows); until it is usable the version shows "validation passed — holdout pending (date)"; holdout accesses that overlap a later validation window are charged to the trial ledger. **Price-only history:** families that need no announcements (F1, F4) may use price history older than the announcement backfill; those years are marked "survivorship unknown (exposed)" and results are shown with and without them; F1 and F4 are exempt from the event-coverage rule (halts inferred per DAT-127). Pre-backfill F4 rows cannot apply F4's "no − polarity event" condition and form a separately labelled variant **"F4-no-event-filter"**, reported separately. **Survivorship:** each year's **missing share** = codes with ≥ 3 announcements in the previous 60 sessions (DAT-125 list — an announcement-only definition) that have no price history in the source, ÷ all such codes; shown per year beside every result. Years with missing share > 5% are marked "survivorship-exposed"; **labels come from the full set** and carry the qualifier "survivorship-exposed (missing share x%)"; the result without exposed years is shown beside it (with its reachable date when not yet computable), and a **delisting sensitivity** re-scores signal-ledger trades in codes delisted within their holding period at the last traded price (or −100% when none); it can only cover delisted codes the source still carries, so it does **not** bound the bias from codes missing entirely — the app says so. Code reuse (same ticker, different entity) is detected from the announcement list and such histories are split. F2, F3 and F6 are validated on **U1-only variants** until own snapshots cover U2; **F5 is descriptive-only** until own snapshots (DAT-130) cover development (≥ 252) + purge + validation + purge + holdout + completion window (≈ 1,330 sessions ≈ 5.3 years at defaults; the date is computed and shown). Every PASSED-BACKTEST label carries the note "v1 rules were written with knowledge of recent market history; only forward evidence is fully out-of-sample." F2 uses "F2-no-fundamentals" and F6 uses "F6-no-insider" variants where PIT data is missing. **Labels attach to the exact variant tested**; when the live rule differs from the validated variant, the tile and leaderboard say "live rule ≠ validated variant".
- **ARN-083** Cost robustness: must pass under P3 + 50% slippage.
- **ARN-084 (s9) Leverage.** Primary test: H0 = sleeve per-trade net expectancy ≤ 0 on the family's own entries, same bootstrap as ARN-081 at α_i ÷ L, each test recorded in the trial ledger (ARN-085). C3 comparison is secondary; L−U CIF differences are descriptive.
- **ARN-085 (s9) Trial ledger and budget:** one **market-level trial ledger** counts every generated challenger, every validation/holdout access, every candle-pattern test (charged to F4's lineage) and every new lineage (FAM-101; each new lineage starts with its own budget m = 20). The budget is **cumulative per frozen validation split** (default m = 20 per lineage, not per year); when it is exhausted, further promotions of that lineage wait for the next rolling holdout (ARN-082); the new budget = 20 − (accesses already made × share of the new validation window that overlaps the old one), rounded up. Lessons do not consume it (ARN-063).
- **ARN-086 (s9) Labels** per (execution, rule version, variant): UNVALIDATED → **PASSED-BACKTEST** (VAL-110 on validation + one holdout confirmation of (i) at one-sided α = 0.05 ÷ L with the same bootstrap) → **CONSISTENT-FORWARD** (≥ 100 forward **signal-ledger** trades at fixed notional and ≥ 6 months, forward per-trade excess over forward matched controls one-sided, tested at 100, 200, 300 … trades with α spent as (0.10 ÷ L) / 2^k at look k, absolute net expectancy > 0, and forward cohort CIF inside the backtest's 90% prediction interval). Negative outcomes, defined by U = the upper limit of the **two-sided 90% interval** of per-trade net excess only: **FAILED** if U < `useful_edge_min` (+0.5% net — a useful edge is excluded); otherwise **NOT-DEMONSTRATED** (the test did not pass but a useful edge is still possible). The minimum detectable effect is shown separately. Also UNVALIDATABLE (event coverage < 90%, DAT-125) and "possible luck" (doubled without PASSED-BACKTEST). Families are labelled with the Bonferroni correction across active lineages of ARN-081. Every label shows its minimum detectable effect and n.
- **ARN-087 = VAL-110 (s9) Validation and promotion test.** On the validation split, a family (or a challenger vs its incumbent) passes iff: (i) per-trade net excess over matched C2 controls > 0 (ARN-081), Bonferroni within the trial budget, **and** the absolute gate of ARN-081 (one-sided 90% lower bound of mean net return > 0 under P5); (ii) challengers only: the per-row excess over control of the challenger's ledger > the incumbent's over the same period including rows present in only one version, using the ARN-081 bootstrap at one-sided α_i ÷ L; (iii) **safety check:** on non-overlapping cohorts over development + validation, Δ(bust + stalled) CIF at 252 sessions vs the C2 comparator with its interval (effective N, ARN-053); it **blocks** promotion only when effective N ≥ 8 and the point estimate > +5 percentage points, otherwise it is shown descriptively with the date it could first block (with ≈ 6 years of history this may be "not reachable", which the app states); (iv) **absolute** per-trade net expectancy (point estimate) > 0 under P3 + 50% slippage; (iv-b) not labelled cost-infeasible (ARN-094); (v) PBO (CSCV per Bailey, Borwein, López de Prado & Zhu 2017; s14; S = 10 blocks, on **weekly** returns of the fixed-notional signal ledger, where a period's return = Σ **daily mark-to-market** P/L of open rows ÷ (A$600 × average open rows) and periods with no open rows are skipped) ≤ 0.2 when ≥ 5 variants of the lineage have been tested, else "n/a"; (vi) Deflated Sharpe Ratio (Bailey & López de Prado 2014, incl. skewness and kurtosis terms; s14) of **daily** returns of the fixed-notional signal ledger (same return definition as (v), days with no open rows skipped), N = the lineage's trials on this validation split (ARN-085), variance of the **daily** Sharpe ratio across tested variants, or `dsr_default_sr_variance` (Ch. 15: daily-frequency Sharpe variance across the 6 families on development data) when fewer than 5, ≥ 0.95. A label reached this way reads "edge vs random entries; positive after costs (lower bound > 0 under P5; point estimate > 0 under stress)". Any other promotion rule in older text is void.

## 5.11 Guardrails
- **ARN-090** Deterministic, versioned rule sets; LLMs never trade.
- **ARN-091** No silent edits; changes via challengers or Owner force-apply (KB-050).
- **ARN-092** Retire a version that is FAILED at one of the ARN-086 forward looks (same α spending), or is dominated.
- **ARN-093 (s9)** Kill switch per family, checked at 20, 40, 60 … forward trades up to K = `killswitch_max_looks_per_year` (set each year from the measured trade rate); each of the 3 criteria uses α = 0.05 ÷ 3 spent as α/2^k across its looks (overall false-trigger rate ≤ 5% per year): forward per-trade expectancy vs backtest; forward win rate vs the backtest distribution; forward CIF below the backtest 90% lower bound once estimable. (No slippage trigger: in a paper system realised slippage equals modelled.)
- **ARN-094** "Cost-infeasible at this seed" label when the development-split **gross mean per-trade return at fixed notional** (before brokerage and slippage) < 2× the round-trip cost of a A$600 trade; it blocks PASSED-BACKTEST (VAL-110 iv-b).

## 5.12 Compute and integrity
- **ARN-100 (s9)** Nightly deterministic compute ≤ 10 min per active market; **weekly light replay ≤ 30 min** (new trades + controls) and **monthly full replay ≤ 90 min**, rotating markets when several are active; shared control path library; M4 delivers a measured budget report.
- **ARN-101 (s9)** Nightly ledger invariants: cash ≥ 0; no shorts; sleeve-margin balance = margin of the open sleeve trade (else 0); sleeve price+financing loss ≤ margin; lock state consistent; NAV reconciles (ARN-051); every trade has costs, a Decision Card, a tier and a filter decision.
- **ARN-102** Cohorts store rule version, parameters, profiles, sleeve settings, data snapshot id, random seed; re-runs reproduce identical results.

- **Given** an F3 event with day-low 1.3 ATR below the entry-day open, **then** its C2 control's initial stop is 1.3 ATR below the control's entry-day open.
- **Given** P5 at A$1,000.00 → A$5.00; at A$1,000.01 → A$10.00.
- **Given** a U3 stock at A$0.20, **then** slippage = 250 bps.
